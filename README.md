# Локальный агент

Свой ИИ-помощник на Windows: чат с моделью на вашем компьютере, инструменты (файлы,
поиск, команды) и автоматический подбор модели под железо. Без облака и аккаунтов.

## Запуск

1. Двойной щелчок по `start.bat` (видно консоль) или `Локальный агент.vbs` (без окна).
2. Откроется браузер на `http://localhost:7867` — это и есть приложение.
3. Нажмите «Запустить» на рекомендованной модели. Первый запуск модели занимает
   20–60 секунд, дальше — мгновенно.

## Что внутри

| Часть | Где | Что делает |
|---|---|---|
| Определение железа | `app/hardware.py` | RAM, CPU, GPU, свободное место |
| Движок llama.cpp | `app/engine.py` | находит, скачивает и обновляет сборки, запускает `llama-server` |
| Подбор модели | `app/scan.py`, `app/catalog.py` | ищет ваши `.gguf`, оценивает, что влезет в память |
| Инструменты | `app/tools.py` | файлы, команды, веб-поиск, время, калькулятор |
| Агент | `app/agent.py` | стриминг ответа + цикл вызова инструментов |
| Сервер и API | `app/main.py` | локальный HTTP на `localhost:7867` |
| Интерфейс | `app/ui/` | чат, модели, настройки |

## Три режима модели (вкладка «Настройки» → «Модель и подключение»)

- **Локально** — приложение поднимает `llama-server` само (кнопки на вкладке «Модели»).
- **Свой сервер** — клиент к уже запущенному OpenAI-совместимому серверу: LM Studio (`:1234`),
  Ollama (`:11434`), vLLM, чужой `llama-server`. Кнопка «Найти серверы» обходит порты
  1234/11434/8080/8000/5000/12345/8090/8091 и предлагает найденное.
- **Внешний API** — OpenAI-совместимые облака (OpenRouter, Groq, DeepSeek, Mistral) и любой
  свой адрес. Ключ хранится зашифрованным в `keys.json`, в настройки и в `/api/state` не попадает.

Модель в памяти можно **выгрузить** одной кнопкой (в шапке чата и на карточке модели) —
память возвращается системе сразу; на карточке видно, сколько памяти занимает текущая модель.

## Тесты

```bash
python tests/smoke_flow.py    # загрузка → свой сервер → чат → выгрузка
python tests/smoke_tools.py   # вызов инструмента и ответ по его результату
python tests/smoke_hf.py      # Hugging Face: поиск моделей, файлы, эмбеддинги
python tests/smoke_jobs.py       # фоновые задачи: загрузка модели, обновление
python tests/smoke_schedule.py   # расписание: сохранить, список, кривое время, удалить
python tests/smoke_attach.py     # вложения: загрузка, чтение, отказы
python tests/smoke_telegram.py   # Telegram: статус, сохранение чата
python tests/smoke_signature.py  # подпись манифеста обновлений
```

## Команда ролей (вкладка «Команда»)

11 ролей как в командном агенте: Аналитик, Архитектор, Базы данных, Разработчик, DevOps, Безопасник, Производительность, Продакт, Исследователь, Ревьюер, Тестировщик. У каждой:

- **что делает** — характер и правило роли (редактируется в таблице);
- **уровень размышлений** — без / низкий / средний / высокий / максимальный (влияет на системный промпт);
- **набор инструментов** — по роли (read/ls/find/grep/bash/web) или «все» (файлы, команды).

Галочка **«Команда ролей (оркестратор)»** над полем ввода отправляет задачу оркестратору: он
составляет план по ролям (`plan`), каждая роль работает со своим контекстом и своими инструментами
(своим набором инструментов), затем оркестратор сводит итог. Видно, кто что сделал.

API: `POST /api/roles`, `POST /api/team`, `POST /api/chat` с `{"mode": "team"}`.

## Внешние инструменты (MCP)

В «Настройках» есть панель **«Внешние инструменты (MCP)»**: это готовые наборы инструментов от
других программ (файловые операции, память, загрузка страниц и т.д.).

- **Готовые наборы** — кнопки «Файлы», «Память», «Загрузка страниц» (запускаются через `npx`/`uvx`).
- **Добавить вручную** — впишите команду запуска, например `npx -y @modelcontextprotocol/server-memory`.
- У каждого сервера кнопки **«Проверить»** (показывает список инструментов, которые он дал) и «Удалить».
- Инструменты попадают к агенту с префиксом `mcp__<сервер>__<имя>`; роли видят их, если в наборе роли есть `mcp`.

Клиент — свой (`app/mcp.py`), JSON-RPC по stdio, без внешних зависимостей.

## Безопасность и управление

- Локальный API защищён токеном: он создаётся при первом запуске в
  `%LOCALAPPDATA%\LocalAgentccess.token` и вшивается в страницу. Свои скрипты должны слать
  заголовок `X-Agent-Token: <токен>` (или `?token=<токен>`), иначе ответ `401`.
- **Опасные действия** (запись файлов, команды) по умолчанию **спрашивают подтверждение**:
  в интерфейсе появляется окно «Агент хочет выполнить write_file … [Разрешить] [Запретить]».
  Переключатель «Опасные действия агента» в настройках: `спрашивать каждый раз` / `автоматически`.
- Кнопка **■ Стоп** рядом с полем ввода прерывает генерацию (модель перестаёт считать сразу).
- Длинный диалог **сжимается автоматически**, чтобы не упираться в контекст: старая часть
  заменяется кратким конспектом (в чате видно пометку «Контекст сжат»).

## Голос

- **Кнопка 🎤** в поле ввода (или `Ctrl+Alt+Space`) — говорите, отпустили/нажали ещё раз — текст
  распознаётся локально (`whisper.cpp`, модель `ggml-base`, ~180 МБ, качается один раз) и уходит в чат.
- **Голосовые команды** без интернета: «новый чат», «выгрузи модель», «включи команду»,
  «выключи команду», «открой папку …». Остальное — одним вопросом.
- **Озвучивание ответов** — переключатель в «Настройках» (Windows SAPI, офлайн, без зависимостей).
- Запись делается прямо в браузере: 16 кГц, моно, WAV — без ffmpeg и внешних утилит.

API: `GET /api/voice`, `POST /api/voice/install`, `POST /api/voice/transcribe`, `POST /api/voice/say`.

## Мониторинг и панели

Всё служебное убрано вниз, чтобы не занимать рабочее место:

- **Строка состояния** внизу экрана: модель и её память, загрузка ЦП, ОЗУ, токены (вход → выход),
  скорость вывода, текущее действие (модель/инструмент), порт.
- Кнопка **«Панели»** раскрывает шторку снизу (как выдвижное меню): «Компьютер», «Ресурсы», «Модель»,
  «Токены и скорость», «Что происходит сейчас», **Чаты** и **Проекты**.
- Над чатом — одна компактная строка: имя модели · память · кнопка «Выгрузить».

API: `GET /api/stats`, `GET /api/chats`, `GET /api/chats/get?id=`, `POST /api/chats/save`,
`POST /api/chats/delete`, `POST /api/projects`.

## Рабочая раскладка (вариант A)

Чат собран из трёх зон: левая панель 280 px, центр, правая панель 300 px; снизу шторка 240 px.

- **Блоки перетаскиваются** за заголовок в любую зону — из панели в шторку и обратно. Место и порядок запоминаются (`localStorage.agentLayout.v2`) и восстанавливаются при запуске.
- **Ширина панелей** — тянуть за разделитель между панелью и чатом (200…480 px), запоминается отдельно.
- **Высота шторки** — тянуть за ручку сверху (120 px … 70% экрана).
- **Свернуть блок** — кнопка в заголовке; состояние тоже запоминается.
- **Сбросить раскладку** — внизу вкладки «Настройки»: блоки возвращаются на места, размеры по умолчанию.
- **Узкий экран**: до 1100 px правая панель уезжает за край и открывается кнопкой «Правая панель» в строке состояния; до 900 px так же ведёт себя левая.

По умолчанию: слева «Чаты», «Проекты и рабочие папки», «Роли»; справа «Модель», «Ресурсы», «Что происходит сейчас»; в шторке «Токены и скорость», «Компьютер», «Настройки модели», «Рекомендация под этот ПК».

## Настройки (вкладка «Настройки»)

- **Менять файлы** — разрешает агенту записывать файлы (по умолчанию выключено).
- **Запускать команды** — разрешает `cmd.exe` (по умолчанию выключено).
- **Искать в интернете** — веб-поиск (включено).
- **Папка моделей** — где лежат `.gguf` (по умолчанию `F:\Models for LMstudio`).
- **Дополнительные папки** — ещё места через `;`. Обычно заполняется само: на вкладке
  «Модели» есть кнопка **«Искать»** — она обходит все локальные диски, находит папки с
  `.gguf` (включая кэши Hugging Face `…/models--автор--имя/snapshots/…`) и запоминает их.
- **Контекст** — 4К…32К токенов.
- **Движок** — кнопки «Vulkan» / «CPU»: скачать свежий llama.cpp из релизов
  `ggml-org/llama.cpp` и переключиться на него.

## Как выбирается модель

Считается бюджет памяти (всего RAM минус резерв системы), затем каждая модель
оценивается: влезает ли файл, сколько останется запаса и сколько параметров активно.
MoE-модели (например 30B-A3B) получают бонус: активных параметров мало, поэтому на
встроенной графике они заметно быстрее плотных моделей того же размера.

## API (для скриптов)

```bash
curl http://localhost:7867/api/state                     # железо, модели, движок
curl -X POST http://localhost:7867/api/model/load \
  -H "Content-Type: application/json" -d '{"path":"F:/.../model.gguf"}'
curl -X POST http://localhost:7867/api/chat \
  -H "Content-Type: application/json" \
  -d '{"messages":[{"role":"user","content":"привет"}]}'   # SSE-поток
```

Внутри работает обычный OpenAI-совместимый сервер `llama-server` на свободном порту
(8090+), поэтому к нему можно подключаться любым клиентом.

## Требования

- Windows 10/11, Python 3.10+ (у вас уже есть), 8 ГБ ОЗУ минимум.
- Никаких `pip install` — только стандартная библиотека.

## База знаний

Вкладка «Знания» — агент ищет ответ в ваших папках и документах и указывает источник.

1. Вставьте путь к папке или файлу и нажмите «Проиндексировать».
2. Пишите вопрос в поле поиска — под ответом видно файл и релевантность.
3. В чате агент делает это сам: у него есть инструмент `search_docs`.

Индекс лежит в `rag.sqlite` рядом с настройками, интернет не нужен.

## Поиск по смыслу (эмбеддинги)

По умолчанию работает поиск по словам: BM25 плюс локальные хеш-векторы. Если на диске есть модель эмбеддингов (например `embeddinggemma`, `bge-m3` или `nomic-embed-text`), приложение поднимает для неё отдельный `llama-server` на свободном порту — чат-модель это не затрагивает.

1. Вкладка «Знания» → «Проверить модель»: показывает размер вектора (768 чисел у большинства моделей).
2. «Пересчитать базу» — заново считает векторы всех источников уже с моделью, это несколько минут.
3. Путь к модели можно задать вручную в «Настройках», иначе берётся первый подходящий файл `.gguf`.

Для русского языка берите многоязычную модель (`bge-m3`, `embeddinggemma`): `nomic-embed-text` понимает в основном английский.

## Модели с Hugging Face

Вкладка «Модели» → подвкладка «В сети: Hugging Face»:

1. Введите слово (`Qwen3`, `bge-m3`, `nomic-embed`) или нажмите готовый запрос.
2. «Показать файлы» — список `.gguf` с размером и квантом, у каждого файла есть кнопка «Скачать».
3. Файл качается в папку моделей, в подпапку `LocalAgent\<автор>--<модель>\`, прогресс видно на месте.

Скачивать можно и приватные модели: токен Hugging Face лежит в «Настройках» и хранится через DPAPI.

## Подписанные обновления

Если в «Настройках» заполнен «Открытый ключ обновлений», приложение принимает только манифесты с верной подписью ECDSA P-256 (Windows CNG, без внешних библиотек). Подпись покрывает версию, ссылку на архив и sha256 — подмена манифеста не проходит.

1. `python sign_update.py keygen` — создаёт `update_private.key` и `update_public.key`; публичный ключ вставьте в Настройки.
2. `python sign_update.py sign manifest.json` — добавляет в манифест поле `signature` и сразу проверяет его.
3. Манифест без подписи или с подменённой ссылкой отклоняется: «Подпись манифеста не совпала».

Проверка: `python tests/smoke_signature.py` — 7 шагов с локальным сервером манифеста.

## Портативная версия

```
python build_portable.py
```

Появится папка `dist\LocalAgent` (~21 МБ): встроенный Python, код, `start.bat`, `stop.bat`,
`shortcut.bat` (ярлык на рабочем столе). Внутри лежит `portable.txt` — из-за него все данные
(настройки, чаты, ключи, индекс) пишутся в `data\` рядом с программой, а не в профиль Windows.
Можно носить на флешке: модели ищутся по дискам, либо положите их в `models\`.

## Автозапуск

Настройки → «Запускать при входе в Windows». Пишется ключ HKCU Run (без прав администратора),
путь указывает на портативный `pythonw.exe`, если сборка портативная.
