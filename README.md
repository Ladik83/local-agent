# Локальный агент

Свой ИИ-помощник на Windows: чат с моделью на вашем компьютере, инструменты (файлы,
поиск, команды) и автоматический подбор модели под железо. Без облака и аккаунтов.

## Запуск

1. Двойной щелчок по `start.bat` (видно консоль) или `Локальный агент.vbs` (без окна).
2. Откроется браузер на `http://localhost:7867` — это и есть приложение.
3. Нажмите «Запустить» на рекомендованной модели. Первый запуск модели занимает
   20–60 секунд, дальше — мгновенно.

## Что внутри

| Часть | Где | Что делает |
|---|---|---|
| Определение железа | `app/hardware.py` | RAM, CPU, GPU, свободное место |
| Движок llama.cpp | `app/engine.py` | находит, скачивает и обновляет сборки, запускает `llama-server` |
| Подбор модели | `app/scan.py`, `app/catalog.py` | ищет ваши `.gguf`, оценивает, что влезет в память |
| Инструменты | `app/tools.py` | файлы, команды, веб-поиск, время, калькулятор |
| Агент | `app/agent.py` | стриминг ответа + цикл вызова инструментов |
| Сервер и API | `app/main.py` | локальный HTTP на `localhost:7867` |
| Интерфейс | `app/ui/` | чат, модели, настройки |

## Три режима модели (вкладка «Настройки» → «Модель и подключение»)

- **Локально** — приложение поднимает `llama-server` само (кнопки на вкладке «Модели»).
- **Свой сервер** — клиент к уже запущенному OpenAI-совместимому серверу: LM Studio (`:1234`),
  Ollama (`:11434`), vLLM, чужой `llama-server`. Кнопка «Найти серверы» обходит порты
  1234/11434/8080/8000/5000/12345/8090/8091 и предлагает найденное.
- **Внешний API** — OpenAI-совместимые облака (OpenRouter, Groq, DeepSeek, Mistral) и любой
  свой адрес. Ключ хранится зашифрованным в `keys.json`, в настройки и в `/api/state` не попадает.

Модель в памяти можно **выгрузить** одной кнопкой (в шапке чата и на карточке модели) —
память возвращается системе сразу; на карточке видно, сколько памяти занимает текущая модель.

## Тесты

```bash
python tests/smoke_flow.py    # загрузка → свой сервер → чат → выгрузка
python tests/smoke_tools.py   # вызов инструмента и ответ по его результату
python tests/smoke_hf.py      # Hugging Face: поиск моделей, файлы, эмбеддинги
python tests/smoke_jobs.py       # фоновые задачи: загрузка модели, обновление
python tests/smoke_schedule.py   # расписание: сохранить, список, кривое время, удалить
python tests/smoke_attach.py     # вложения: загрузка, чтение, отказы
python tests/smoke_telegram.py   # Telegram: статус, сохранение чата
python tests/smoke_signature.py  # подпись манифеста обновлений
```

## Команда ролей (вкладка «Команда»)

11 ролей как в командном агенте: Аналитик, Архитектор, Базы данных, Разработчик, DevOps, Безопасник, Производительность, Продакт, Исследователь, Ревьюер, Тестировщик. У каждой:

- **что делает** — характер и правило роли (редактируется в таблице);
- **уровень размышлений** — без / низкий / средний / высокий / максимальный (влияет на системный промпт);
- **набор инструментов** — по роли (read/ls/find/grep/bash/web) или «все» (файлы, команды).

Галочка **«Команда ролей (оркестратор)»** над полем ввода отправляет задачу оркестратору: он
составляет план по ролям (`plan`), каждая роль работает со своим контекстом и своими инструментами
(своим набором инструментов), затем оркестратор сводит итог. Видно, кто что сделал.

API: `POST /api/roles`, `POST /api/team`, `POST /api/chat` с `{"mode": "team"}`.

## Инструменты и MCP

Для этого есть отдельная вкладка **«Инструменты»**.

- **Встроенные инструменты** — 13 штук: файлы, поиск по папке и по тексту, команды, интернет, страницы, время, калькулятор, база знаний. Галочка выключает инструмент целиком; серые недоступны, пока в «Настройках» не разрешены запись файлов, команды или интернет.
- **Авто-выбор под задачу** — галочка вверху. Перед каждым вопросом агент оставляет только нужное: «прочитай файл» → чтение файла, «сколько будет 15%» → калькулятор, «привет» → без инструментов. В чате появляется строка «Инструменты под задачу: …», чтобы было видно, что выбрано.
- **Каталог MCP-серверов** — 13 готовых серверов: файлы, память (граф знаний), пошаговые рассуждения, загрузка страниц, git, SQLite, время, GitHub, Brave-поиск, браузер, PostgreSQL, Docker и проверочный. У каждого — описание, категория, команда запуска и что нужно (Node.js или Python/uv); вверху показано, что установлено на компьютере.
- **Подключение** — кнопка «Подключить» добавляет сервер в настройки и запускает его; «Отключить» убирает. У подключённого сервера видны его инструменты и кнопка «Проверить».
- **Добавить вручную** — любая команда запуска MCP-сервера, например `npx -y @modelcontextprotocol/server-memory`. Пути-заготовки `%HOME%`, `%DATA%`, `%CWD%` подставляются автоматически.

Инструменты MCP приходят к агенту с префиксом `mcp__<сервер>__<имя>`. Клиент свой (`app/mcp.py`), JSON-RPC по stdio, без внешних зависимостей; на Windows команды вида `npx.cmd` запускаются через `cmd.exe /c`.

API: `GET /api/tools` (каталог, состояние, что разрешено), `POST /api/tools/toggle`, `POST /api/tools/auto`, `POST /api/tools/pick` (проверить выбор для текста), `GET /api/mcp`, `POST /api/mcp/add|remove|test`.

Проверки: `python tests/check_tools.py` (23 проверки, включая качество выбора), `python tests/smoke_mcp_catalog.py` (живой запуск сервера и вызов инструмента).

## Навыки агента

Навык — короткая проверенная инструкция под типовой класс задач: «правки кода с проверкой», «разбор ошибки», «ответ по своим документам», «найти нужное в проекте», «проверка перед сдачей». Это не код и не плагины — просто текст в формате:

```
---
name: правки-кода
title: Правки кода с проверкой
when: правка, изменить код, рефакторинг, починить, баг
tags: код, правка, тест
---
1. Сначала прочитай файл целиком…
```

- Файлы лежат в папке данных: `<данные>\skills\<имя>\SKILL.md` (путь виден во вкладке «Инструменты» → «Навыки агента»).
- Агент сам подбирает 1–2 навыка под текст задачи: сначала по словам из `when`/`tags`, потом по смысловой близости заголовков. В чате появляется строка «Навыки: …».
- Навык приходит отдельным системным сообщением и не раздувает основной промпт: тело обрезается до 1600 символов.
- Встроенных пять, они добавляются при первом запуске; кнопка «Добавить встроенные» вернёт их, если удалили.
- Свои навыки: положите папку с `SKILL.md` в каталог навыков — они появятся в списке и в подборе без перезапуска (кэш 20 секунд).

API: `GET /api/skills`, `POST /api/skills/seed`, `POST /api/skills/save`, `POST /api/skills/delete`.

## План задачи и проверка

- **План.** Инструмент `todo_write` — агент сам записывает шаги задачи и отмечает выполнение. План показывается плашкой над перепиской: `● сделано`, `◐ в работе`, `○ впереди`, внизу «Выполнено N из M». План подставляется в системное сообщение, поэтому агент помнит, на каком шаге остановился, даже после сжатия истории.
- **Проверка.** Инструмент `verify_project` подбирает проверку под проект: `npm test`, `make test`, `pytest`, иначе — проверку синтаксиса (`python -m compileall`). Возвращает команду, код возврата и хвост вывода. Требует разрешения «команды» в настройках; в авто-подборе доступен всегда, когда команды разрешены.
- **Правило в работе:** после правок агент обязан прогнать проверку и чинить, пока не зелено — это записано в навыке «Правки кода с проверкой».

Проверки: `python tests/check_agent_context.py` — поднимает фальшивую модель, смотрит, что реально ушло в запрос (системные сообщения с навыком и планом, набор инструментов, заметки).

- **Кнопка «Агент»** в строке режимов: включена — модель пользуется инструментами, файлами и ведёт план; выключена — обычный чат без доступа к диску и командам. Состояние сохраняется.
- **Всё управление моделью — в правой панели**: выбор, «Загрузить/Выгрузить», размеры и параметры, а после загрузки — адрес `http://127.0.0.1:<порт>/v1` с кнопкой «Копировать» для подключения других приложений.

## Режим работы и примеры задач

Строка **«Режим работы»** стоит под полем ввода, в той же карточке (сначала поле с кнопками, ниже — режимы): **Один** — отвечает одна модель, **Команда** — задачу разбирают несколько ролей, **Агент** — включает инструменты (файлы, поиск, проверки, план). Кнопки одинаковой ширины, состояние «Агент» подсвечено, когда он включён.

Над карточкой — восемь готовых формулировок по центру: проверить папку, ревью кода, найти в знаниях, собрать ТЗ, тесты, README, сравнить файлы, безопасность. Клик подставляет текст в поле ввода, его можно поправить.

## Свои роли

Вкладка **«Команда»** — список ролей слева, редактор справа. У каждой роли: название, уровень размышлений, набор инструментов (все / только чтение / чтение и команды) и описание, что она делает.

- **«+ Добавить роль»** создаёт новую роль; название и описание можно вписать руками.
- **«Придумать описание»** просит загруженную модель написать описание по названию (2–3 предложения) — текст потом правится в поле.
- **«Удалить роль»** убирает роль, **«Сбросить»** возвращает стандартные, **«Сохранить роли»** запоминает.

## Субагенты (параллельные роли)

Инструмент для сложных задач: несколько ролей получают одну задачу одновременно, каждая в своём контексте, затем главная модель сводит ответы в короткий итог.

- `GET /api/subagents/roles` — список ролей, из которых можно выбирать.
- `POST /api/subagents/run {"task": "…", "roles": ["analytics", "dev"]}` — запускает фоновую задачу `subagents`; прогресс виден через `GET /api/jobs`.
- Внутри: до 4 ролей, не больше 3 одновременно (`ThreadPoolExecutor`), каждая — свой системный промпт и правило «только суть», без истории и инструментов. Ошибка одной роли не роняет остальные.
- Итог: один запрос к главной модели со всеми ответами (каждый обрезан до 1200 символов); если модель недоступна — детерминированная склейка «Роль: ответ».
- События для интерфейса: `subagent_start`, `subagent_done`, `note` — сохраняются в задаче и читаются по `GET /api/jobs`.

## План задачи за чатом

- План хранится по чату: `GET /api/plan?chat=ID`, `POST /api/plan/save {chat,title,steps}`, `POST /api/plan/reset {chat}`.
- Файл: `<данные>\chats\<chat_id>.plan.json`, запись атомарная (`.tmp` → `replace`), имя чата санитизируется.
- Интерфейс отправляет `chat` вместе с сообщением, поэтому план восстанавливается при открытии чата и после перезапуска приложения.
- Без `chat` (старый API) план живёт в памяти процесса, как раньше.

## Навыки: редактор

Во вкладке «Инструменты» → «Навыки агента»: «Новый навык», у каждого — «Изменить» и «Удалить». Редактор — модальное окно с полями имени, заголовка, «когда применять», тегов и текста; файл `SKILL.md` собирается с фронтматтером автоматически. Чтение одного навыка — `GET /api/skills/one?name=…`.

## Внешние агенты

`GET /api/agents/info` отдаёт адрес нашего OpenAI-совместимого API и готовые строки подключения для Cline, Continue, opencode и Hermes Agent. Блок в «Настройках» показывает адрес, модель, состояние и копирует адрес в буфер. Claude Code и Codex CLI напрямую не подключатся — им нужен прокси под Anthropic/Responses API.

## Безопасность и управление

- Локальный API защищён токеном: он создаётся при первом запуске в
  `%LOCALAPPDATA%\LocalAgentccess.token` и вшивается в страницу. Свои скрипты должны слать
  заголовок `X-Agent-Token: <токен>` (или `?token=<токен>`), иначе ответ `401`.
- **Опасные действия** (запись файлов, команды) по умолчанию **спрашивают подтверждение**:
  в интерфейсе появляется окно «Агент хочет выполнить write_file … [Разрешить] [Запретить]».
  Переключатель «Опасные действия агента» в настройках: `спрашивать каждый раз` / `автоматически`.
- Кнопка **■ Стоп** рядом с полем ввода прерывает генерацию (модель перестаёт считать сразу).
- Длинный диалог **сжимается автоматически**, чтобы не упираться в контекст: старая часть
  заменяется кратким конспектом (в чате видно пометку «Контекст сжат»).

## Голос

- **Кнопка 🎤** в поле ввода (или `Ctrl+Alt+Space`) — говорите, отпустили/нажали ещё раз — текст
  распознаётся локально (`whisper.cpp`, модель `ggml-base`, ~180 МБ, качается один раз) и уходит в чат.
- **Голосовые команды** без интернета: «новый чат», «выгрузи модель», «включи команду»,
  «выключи команду», «открой папку …». Остальное — одним вопросом.
- **Озвучивание ответов** — переключатель в «Настройках» (Windows SAPI, офлайн, без зависимостей).
- Запись делается прямо в браузере: 16 кГц, моно, WAV — без ffmpeg и внешних утилит.

API: `GET /api/voice`, `POST /api/voice/install`, `POST /api/voice/transcribe`, `POST /api/voice/say`.

## Мониторинг и панели

Всё служебное убрано вниз, чтобы не занимать рабочее место:

- **Строка состояния** внизу экрана: модель и её память, загрузка ЦП, ОЗУ, токены (вход → выход),
  скорость вывода, текущее действие (модель/инструмент), порт.
- Кнопка **«Панели»** раскрывает шторку снизу (как выдвижное меню): «Компьютер», «Ресурсы», «Модель»,
  «Токены и скорость», «Что происходит сейчас», **Чаты** и **Проекты**.
- Над чатом — одна компактная строка: имя модели · память · кнопка «Выгрузить».

API: `GET /api/stats`, `GET /api/chats`, `GET /api/chats/get?id=`, `POST /api/chats/save`,
`POST /api/chats/delete`, `POST /api/projects`.
- **Блоки обновляются на месте, без перерисовки**: цифры не дёргаются, полоски загрузки не пульсируют — меняется только значение, а не размер блока.
- **Прокрутка не отнимает ширину**: место под полосу прокрутки зарезервировано, поэтому панель не «прыгает» при появлении ползунка.

## Рабочая раскладка (вариант A)

Чат собран из трёх зон: левая панель 280 px, центр, правая панель 300 px; снизу шторка 240 px.

- **Блоки перетаскиваются** за заголовок в любую зону — из панели в шторку и обратно. Место и порядок запоминаются (`localStorage.agentLayout.v2`) и восстанавливаются при запуске.
- **Ширина панелей** — тянуть за разделитель между панелью и чатом (200…480 px), запоминается отдельно.
- **Высота шторки** — тянуть за ручку сверху (120 px … 70% экрана).
- **Свернуть блок** — кнопка в заголовке; состояние тоже запоминается.
- **Сбросить раскладку** — внизу вкладки «Настройки»: блоки возвращаются на места, размеры по умолчанию.
- **Узкий экран**: до 1100 px правая панель уезжает за край и открывается кнопкой «Правая панель» в строке состояния; до 900 px так же ведёт себя левая.

- **Блок «Роли»** — «Список ролей» раскрывает перечень с подсказкой при наведении: сколько думает, какие инструменты, что делает. Клик закрепляет полное описание, Esc закрывает. Переход на вкладку «Команда» — по шестерёнке в заголовке блока.

- **Режимы «Один / Команда»** стоят в строке выбора модели (полные подписи — в подсказках), а примеры задач — мелкие чипы в одну строку: рабочая область чата выросла на ~60 px.

- **Нижняя полоса «Панели»** сворачивается в тонкую строку 38 px: видно название и состав (какие блоки внутри), клик по полосе или кнопке «Панели» в строке состояния разворачивает обратно. Состояние запоминается, чат получает +200 px.

По умолчанию: слева «Чаты», «Проекты и рабочие папки», «Роли»; справа «Модель», «Ресурсы», «Что происходит сейчас»; в шторке «Токены и скорость», «Компьютер», «Настройки модели», «Рекомендация под этот ПК».

## Настройки (вкладка «Настройки»)

- **Менять файлы** — разрешает агенту записывать файлы (по умолчанию выключено).
- **Запускать команды** — разрешает `cmd.exe` (по умолчанию выключено).
- **Искать в интернете** — веб-поиск (включено).
- **Папка моделей** — где лежат `.gguf` (по умолчанию `F:\Models for LMstudio`).
- **Дополнительные папки** — ещё места через `;`. Обычно заполняется само: на вкладке
  «Модели» есть кнопка **«Искать»** — она обходит все локальные диски, находит папки с
  `.gguf` (включая кэши Hugging Face `…/models--автор--имя/snapshots/…`) и запоминает их.
- **Контекст** — 4К…32К токенов.
- **Движок** — кнопки «Vulkan» / «CPU»: скачать свежий llama.cpp из релизов
  `ggml-org/llama.cpp` и переключиться на него.

## Как выбирается модель

Считается бюджет памяти (всего RAM минус резерв системы), затем каждая модель
оценивается: влезает ли файл, сколько останется запаса и сколько параметров активно.
MoE-модели (например 30B-A3B) получают бонус: активных параметров мало, поэтому на
встроенной графике они заметно быстрее плотных моделей того же размера.

## API (для скриптов)

```bash
curl http://localhost:7867/api/state                     # железо, модели, движок
curl -X POST http://localhost:7867/api/model/load \
  -H "Content-Type: application/json" -d '{"path":"F:/.../model.gguf"}'
curl -X POST http://localhost:7867/api/chat \
  -H "Content-Type: application/json" \
  -d '{"messages":[{"role":"user","content":"привет"}]}'   # SSE-поток
```

Внутри работает обычный OpenAI-совместимый сервер `llama-server` на свободном порту
(8090+), поэтому к нему можно подключаться любым клиентом.

## Требования

- Windows 10/11, Python 3.10+ (у вас уже есть), 8 ГБ ОЗУ минимум.
- Никаких `pip install` — только стандартная библиотека.

## База знаний

Вкладка «Знания» — агент ищет ответ в ваших папках и документах и указывает источник.

1. Вставьте путь к папке или файлу и нажмите «Проиндексировать».
2. Пишите вопрос в поле поиска — под ответом видно файл и релевантность.
3. В чате агент делает это сам: у него есть инструмент `search_docs`.

Индекс лежит в `rag.sqlite` рядом с настройками, интернет не нужен.

## Поиск по смыслу (эмбеддинги)

По умолчанию работает поиск по словам: BM25 плюс локальные хеш-векторы. Если на диске есть модель эмбеддингов (например `embeddinggemma`, `bge-m3` или `nomic-embed-text`), приложение поднимает для неё отдельный `llama-server` на свободном порту — чат-модель это не затрагивает.

1. Вкладка «Знания» → «Проверить модель»: показывает размер вектора (768 чисел у большинства моделей).
2. «Пересчитать базу» — заново считает векторы всех источников уже с моделью, это несколько минут.
3. Путь к модели можно задать вручную в «Настройках», иначе берётся первый подходящий файл `.gguf`.

Для русского языка берите многоязычную модель (`bge-m3`, `embeddinggemma`): `nomic-embed-text` понимает в основном английский.

## Модели с Hugging Face

Вкладка «Модели» → подвкладка «В сети: Hugging Face»:

1. Введите слово (`Qwen3`, `bge-m3`, `nomic-embed`) или нажмите готовый запрос.
2. «Показать файлы» — список `.gguf` с размером и квантом, у каждого файла есть кнопка «Скачать».
3. Файл качается в папку моделей, в подпапку `LocalAgent\<автор>--<модель>\`, прогресс видно на месте.

Скачивать можно и приватные модели: токен Hugging Face лежит в «Настройках» и хранится через DPAPI.

## Обновление движка llama.cpp

В «Настройках» есть блок «Движок llama.cpp»: какая версия установлена, какая сборка вышла на GitHub, когда проверяли.

- **«Проверить сейчас»** — сверяет установленный тег с последним релизом llama.cpp (`GET /api/engine/check`), показывает время проверки и, если вышла новая сборка, строку «Обновление движка: доступно bNNNNN» с кнопкой «Обновить».
- **«Обновить»** — скачивает свежую сборку того же варианта (Vulkan или CPU), распаковывает и переключает движок; старые сборки остаются на диске для отката.
- **«Проверять при запуске»** — при старте приложения версия сверяется с GitHub в фоне (результат виден в блоке и в состоянии `/api/state` → `engine_check`).
- Если интернета нет, проверка честно пишет ошибку и не ломает запуск.

На сегодня (проверка 2026-11-22): установлено **b12628** (Vulkan), на GitHub — **b12631**, то есть доступно обновление.

Проверки: `python tests/check_engine.py`.

## Обновление приложения

В «Настройках» есть строка «Адрес манифеста обновлений» и кнопка **«Проверить обновление приложения»**.

- Приложение читает манифест (`GET /api/update/check`) и сравнивает версии: «У вас 0.6.0, доступна 0.7.0 — что нового» либо «У вас последняя версия 0.6.0».
- Если версия новее, рядом появляется кнопка **«Обновить»**: скачивает архив из манифеста, проверяет sha256 и подпись, распаковывает и подменяет файлы приложения (текущая версия уходит в резервную копию), затем перезапуск.
- Адрес сохраняется в настройках, поле допускает `https://` и локальный `http://127.0.0.1` — удобно проверять манифест на своём же компьютере.
- Без заполненного «Открытого ключа» принимаются любые манифесты; с ключом — только подписанные.

Формат манифеста и подпись — в разделе «Подписанные обновления» ниже.

## Подписанные обновления

Если в «Настройках» заполнен «Открытый ключ обновлений», приложение принимает только манифесты с верной подписью ECDSA P-256 (Windows CNG, без внешних библиотек). Подпись покрывает версию, ссылку на архив и sha256 — подмена манифеста не проходит.

1. `python sign_update.py keygen` — создаёт `update_private.key` и `update_public.key`; публичный ключ вставьте в Настройки.
2. `python sign_update.py sign manifest.json` — добавляет в манифест поле `signature` и сразу проверяет его.
3. Манифест без подписи или с подменённой ссылкой отклоняется: «Подпись манифеста не совпала».

Проверка: `python tests/smoke_signature.py` — 7 шагов с локальным сервером манифеста.

## Зрение (картинки)

Работает с любой GGUF-моделью, у которой рядом лежит проектор `mmproj*.gguf` — привязки к конкретной модели нет.

- **Основная модель со зрением.** Если у выбранной чат-модели есть `mmproj`, движок запускается с `--mmproj`, и картинки идут прямо в неё, вместе с инструментами.
- **Отдельный слот зрения.** Если у основной модели проектора нет, при первой картинке поднимается второй `llama-server` (`app/vision.py`) на своём порту с моделью и проектором; чат-модель при этом даже не загружается. Слот остаётся в памяти до «Выгрузить».
- **Выбор модели.** «Настройки» → «Модель зрения»: `авто` берёт самую лёгкую модель с проектором, у которой в имени есть признак зрения (`-vl`, `vision`, `llava`, `gemma-3` и т. п.); можно указать конкретный файл. Кнопки «Запустить» и «Выгрузить», там же состояние: модель, память, порт.
- **Как прикрепить.** Перетащите картинку в чат или нажмите скобку — появится чип с рамкой. При отправке картинка уходит как `image_url` (base64), текстовая часть — как обычно.
- **Выключить.** «Зрение: разбирать картинки» — снятая галочка отключает маршрут, картинки игнорируются с понятной строкой в чате.
- **Служебные строки** в чате показывают, какая модель разбирает картинку.

API: `GET /api/vision/models`, `POST /api/vision/start`, `POST /api/vision/stop`; статус — в `/api/state` → `vision` и в `/api/stats` → `vision`.

Проверки: `python tests/check_vision.py` (16 статических), `python tests/smoke_vision.py` (рисует картинку, поднимает слот, спрашивает модель), `python tests/probe_vision_route.py` (маршрут `/api/chat` с картинкой на живом сервере).

## Портативная версия

```
python build_portable.py
```

Появится папка `dist\LocalAgent` (~21 МБ): встроенный Python, код, `start.bat`, `stop.bat`,
`shortcut.bat` (ярлык на рабочем столе). Внутри лежит `portable.txt` — из-за него все данные
(настройки, чаты, ключи, индекс) пишутся в `data\` рядом с программой, а не в профиль Windows.
Можно носить на флешке: модели ищутся по дискам, либо положите их в `models\`.

## Автозапуск

Настройки → «Запускать при входе в Windows». Пишется ключ HKCU Run (без прав администратора),
путь указывает на портативный `pythonw.exe`, если сборка портативная.
