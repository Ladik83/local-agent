# Архитектура рабочего пространства «Локальный агент»

**Статус:** проект, к реализации не приступали
**Область:** `app/ui/` — `index.html` (~320 строк), `style.css` (~590 строк), `app.js` (~2300 строк), `panels.js` (~715 строк)
**Ограничения:** только стандартная библиотека Python на бэкенде, только ванильные HTML/CSS/JS на фронтенде. Никаких сборщиков, npm, React/Vue, CSS-фреймворков.
**Все числа в документе — CSS-пиксели, замерены в браузере** на текущей сборке (макет отрисован из `app/ui/*` с заменой абсолютных путей `/ui/` на относительные; сервер приложения не запускался, данные API не запрашивались).

**Срез:** `app/ui` правится параллельно с этим документом, поэтому инвентаризация (§1) — состояние на 22.11, 00:13. Привязка — по селекторам и id; номера строк в `index.html` на момент среза стабильны, в `style.css` они уже смещались, поэтому CSS цитируется селекторами. Дефект D1 (коллизия `.bar`) к моменту сдачи в рабочем дереве устранён — это отмечено в таблице.

## 0. Кратко

1. Центральная колонка жёстко ограничена по ширине: в срезе — `max-width: 980px` на `.view`, в текущем дереве — переменная `--view-max` (1440 px, для чата 1100). Даже 1440 оставляет 25% пустого места на 1920 и 62% на 3840: на 4K видно те же 3–4 карточки моделей, что на ноутбуке. Нужна не константа, а текучая сетка с пределами для текста.
2. Шапка была сломана коллизией классов: `<header class="bar">` и `.bar` для полосы прогресса. На снимке 22.11 00:06 её высота была **25 px** вместо 62, содержимое обрезано `overflow: hidden`, появились чужие отступы `margin: 4px 0 10px` (обрезанный логотип, надпись «не загружена» в две строки). К моменту сдачи документа коллизия в рабочем дереве уже устранена — полоса переименована в `.meter`, шапка снова 62 px. Урок остаётся: короткие имена вроде `.bar` переиспользовать нельзя.
3. Нижняя шторка «Панели» открывается на **286 px** и съедает область сообщений: на 1366×768 остаётся **137 px** — два-три сообщения. Это главная причина жалобы «элементы занимают место».
4. Вся нижняя панель — три равные колонки по 437 px, внутри которых лежат 9 разнородных блоков без общей логики. Пропорции `0.95fr 1fr 1.15fr` и `1.15fr 1fr 1fr` не работают: `display:flex` перебивает `grid-template-columns` (4 объявления `.drawerGrid` подряд).
5. Статус модели дублируется в **4 местах**, кнопка загрузки модели — в **5 местах**, настройка контекста — в **3 контролах**. Настройки — 8 панелей, 16 строк, **1387 px** контента при 664 px видимой области (2,1 экрана прокрутки).
6. Каждые **1,5 с** приложение делает 3 запроса и **16 перезаписей `innerHTML`** (7 в статусе, 4 в метриках, 5 в панелях), причём 3 блока перерисовываются дважды. `renderTuning()` пересобирает `<select>` каждые 1,5 с — ввод в поле «Своё значение» стирается на полуслове.
7. Целевая схема: **шапка 48 + левая панель 248 + центр 830 + правая 288 + док 28 + статус 28** на 1366×768. Область сообщений — **536 px** вместо 423 (+27%), с открытым доком — **336 px** вместо 137 (+145%). На 1920 центр — **1292 px** вместо 980 (+32%).
8. Вместо трёх колонок-свалок — **Kanban-полосы**: левая, правая, нижний док и «склад» скрытых блоков. 14 блоков перетаскиваются мышью и с клавиатуры, раскладка хранится в `localStorage.agentLayout.v2`, размеры панелей — авто по брейкпоинтам плюс ручная подстройка.

### 2.3 Правило «одна сущность — один блок»

Каждый блок из §3 — это **один DOM-узел**, который монтируется в контейнер. Перетаскивание = `container.appendChild(node)`, а не копирование разметки. Поэтому:

- «Модель» в правой панели и «Модель» на вкладке «Модели» — один и тот же узел: вкладка «Модели» просто разворачивает его в центр и добавляет список моделей.
- Чаты в левой панели и чаты в доке — один узел, не два списка.
- Настройки модели (`tuning`) на вкладке «Модели» и в правой панели — один узел.

Ограничение: узел не может быть в двух местах. Если пользователь перетащил «Модель» в док, в правой панели остаётся только её заголовок-заглушка «Модель → в доке» (клик переносит обратно). Это лучше, чем два независимых рендера, которые расходятся по состоянию.

Чип модели в шапке — единственное место, где состояние модели видно всегда. Он же заменяет `.modelRow` в чате и `#sbModel` в статусе (в статусе остаётся короткое имя без префикса «модель:»).

### 2.6 Нижний док

Три состояния:

- **Свёрнут** (по умолчанию при высоте окна <900): полоса 28 px с ручкой и счётчиком «Логи · 3 задачи».
- **Открыт** 200 px: горизонтальная полоса блоков, `grid-template-columns: repeat(auto-fit, minmax(280px, 1fr))`, максимум 3 блока в ряд.

### 3.3 Правила перетаскивания

**Зоны приёма:** `.lane[data-lane="left"]`, `.lane[data-lane="right"]`, `.lane[data-lane="bottom"]`, панель «Склад» (`.pool`, открывается кнопкой в доке или `Alt+0`). Центр — не зона приёма для блоков полос (там живёт вкладка).

**Механика:**

1. `pointerdown` на `.blk-grip` (иконка ⠿, 24×24, `touch-action: none`), `setPointerCapture`.
2. Порог 4 px: до него — обычный клик (сворачивание блока), после — старт перетаскивания.
3. `body.dragging` — `user-select: none`, `cursor: grabbing`, блоки получают `pointer-events: none`.
4. Призрак: `cloneNode(true)`, `position: fixed`, ширина = ширина исходного блока, `transform: translate3d()`, `opacity: .92`, `pointer-events: none`, `z-index: 500`.
5. Исходный блок остаётся на месте с `opacity: .35` (не удаляется — меньше перерисовок).
6. Индикатор вставки: линия 2 px `var(--accent)` между блоками, позиция — по середине высоты соседей (`e.clientY` против `rect.top + rect.height/2`).
7. Автопрокрутка полосы: если курсор в 24 px от края, `scrollTop += 8` за кадр.
8. `pointerup`: коммит (перенос узла), анимация FLIP 160 мс, сохранение раскладки.
9. `Esc` во время перетаскивания — отмена, блок возвращается.
10. `pointercancel` (потеря фокуса окна, Alt+Tab) — отмена, не коммит.

**Ограничения:**

- Максимум 6 блоков в боковой полосе, 3 в доке. При попытке положить 7-й — подсветка красным и `toast` «В полосе максимум 6 блоков».
- Если ширина полосы меньше `min-width` блока — полоса расширяется до `min-width + 16` (с анимацией 120 мс), но не более 45% окна. Если и это невозможно — блок не принимается, подсветка красным.
- Блок нельзя положить сам в себя или между своих же детей.
- Перетаскивание блока в «Склад» = скрыть; на складе блоки показываются списком с кнопкой «Вернуть».
- После перетаскивания — `toast` с «Отменить» на 8 с (одно действие, `Ctrl+Z` тоже работает).

**Во время перетаскивания опрос данных приостанавливается** (`LAYOUT.dragActive = true` → `pollStats` пропускает тик). Иначе `panels.js` перепишет `innerHTML` блока под курсором и узел-призрак «оторвётся».

### 3.4 Клавиатура и доступность

Перетаскивание мышью — не единственный путь:

- Заголовок блока — `<h3><button class="blk-grip" aria-describedby="blk-hint">`. `Enter`/`Space` — меню «Переместить в…» (левая / правая / док / склад), стрелки — выбор, `Enter` — применить.
- `Alt+↑/↓` — блок выше/ниже в своей полосе.
- `Alt+Shift+←/→` — перенос в соседнюю полосу.
- `Alt+1/2/3/0` — сразу в левую / правую / док / склад.
- `Alt+←/→` на ручке-разделителе — ширина ±16 px, `Shift` — ±48, `Home/End` — минимум/максимум.
- Каждое перемещение объявляется через `aria-live="polite"`: «Блок „Модель“ перемещён в правую панель, позиция 2 из 3».
- Заголовок блока — `aria-expanded` для свёрнутости, тело — `role="region" aria-labelledby`.
- Фокус после переноса остаётся на ручке блока (не теряется).

### 3.5 Формат хранения

Ключ `agentLayout.v2`. Пишется с задержкой 250 мс после последнего изменения, одноразово на `pointerup`.

```json
{
  "v": 2,
  "customized": true,
  "lanes": {
    "left":   ["chats", "projects", "kb", "tasks"],
    "right":  ["model", "resources", "now"],
    "bottom": ["logs", "tokens"]
  },
  "pool": ["tools", "roles", "voice", "advice", "tuning"],
  "collapsed": { "left": false, "right": false, "dock": true },
  "blocks": { "chats": { "open": true }, "kb": { "open": true }, "logs": { "open": true } },
  "sizes": {
    "left":  { "px": 248, "auto": true },
    "right": { "px": 288, "auto": true },
    "dock":  { "px": 200, "auto": true }
  }
}
```

Правила чтения:

- Нет ключа → дефолт по таблице §3.2.
- Неизвестный id в `lanes`/`pool` → игнорируется (старая раскладка после обновления не ломает вид).
- Блок есть в реестре, но отсутствует в файле → добавляется в конец своей дефолтной полосы.
- Битый JSON или `localStorage` недоступен → дефолт, без падения (try/catch, как сейчас в `wireResizers`).

Старые ключи `agentTheme`, `agentFont`, `agentModelsTab`, `agentAccState`, `agentDrawerWidths` **не удаляются**. `agentAccState` (состояние `details`) заменяется на `blocks[*].open`, но при первом запуске значения переносятся по совпадению подписей — иначе у пользователя всё схлопнется.

### 3.6 Сброс и миграция

- Кнопка «Раскладка → По умолчанию» в «Настройках → Приложение» и в контекстном меню пустого места полосы.
- Перед сбросом — `confirm()`-модалка с превью: «Вернуть 4 блока влево, 3 вправо, 2 в док, 5 на склад?».
- Экспорт/импорт раскладки — не нужен в v1; при переносе профиля на другой ПК раскладка не переносится (это локальный `localStorage`, не `%LOCALAPPDATA%\LocalAgent`).

## 4. Динамические размеры

### 4.1 Брейкпоинты по ширине

Все значения — CSS-переменные на `:root`, пересчитываются в `applyLayout()` (один `requestAnimationFrame` на `resize`).

| Ширина окна | `--rail-left` | `--rail-right` | Центр | Док | Режим |
|---|---|---|---|---|---|
| ≥2560 | 300 | 360 | 1fr, ≥1700 | 240 | всё видно |
| 1920–2559 | 288 | 340 | 1fr, ≥1250 | 220 | всё видно |
| 1600–1919 | 272 | 320 | 1fr, ≥980 | 200 | всё видно |
| 1440–1599 | 264 | 312 | 1fr, ≥840 | 200 | всё видно |
| 1280–1439 | 248 | 288 | 1fr, ≥720 | 180 | всё видно |
| 1100–1279 | 232 | **44** | 1fr, ≥800 | 170 | правая свёрнута в иконки |
| 900–1099 | **44** | **44** | 1fr, ≥780 | 160 | обе свёрнуты, раскрываются оверлеем 280/300 |
| <900 | оверлей 280 | оверлей 300 | 100% | 150 | панели поверх, закрываются по `Esc` |

Проверка суммы: 1280 − 248 − 288 = 744 ≥ 720 ✓. 1100 − 232 − 44 = 824 ≥ 800 ✓. 900 − 88 = 812 ≥ 780 ✓.

Свёрнутая полоса — 44 px: иконки блоков 32×32 в столбик, подсказка при наведении, клик разворачивает. Свёрнутость хранится в `layout.collapsed` и не сбрасывается при изменении размера окна.

### 4.2 Брейкпоинты по высоте

| Высота | Что меняется |
|---|---|
| ≥1000 | док по умолчанию 220, чаты показывают 10 пунктов |
| 900–999 | док по умолчанию 200 |
| 720–899 | док **свёрнут** (28), композер 48, режимы 32 |
| 600–719 | скрывается `.hint`-подобная мелочь, статус 24, `resources` показывает только ЦП и ОЗУ |
| <600 | статус 24, вкладки в одну строку с прокруткой, чат занимает всё, кроме шапки |

### 4.3 Алгоритм автоподбора

```js
function autoSizes(w, h) {
  var t = w >= 2560 ? [300, 360, 240]
        : w >= 1920 ? [288, 340, 220]
        : w >= 1600 ? [272, 320, 200]
        : w >= 1440 ? [264, 312, 200]
        : w >= 1280 ? [248, 288, 180]
        : w >= 1100 ? [232, 44,  170]
        : w >= 900  ? [44,  44,  160]
        :             [280, 300, 150];      // оверлеи
  if (h < 720) t[2] = 0;                    // док свёрнут
  return { left: t[0], right: t[1], dock: t[2] };
}
```

Применение — только запись трёх переменных:

```js
root.style.setProperty('--rail-left',  left + 'px');
root.style.setProperty('--rail-right', right + 'px');
root.style.setProperty('--dock-h',     dock + 'px');
```

Один style-write → одна перерисовка. Никаких `element.style.width` по каждому блоку.

### 4.4 Ручная подстройка мышью

Ручки: между левой полосой и центром, между центром и правой, сверху дока.

- Видимая полоса 2 px (`::before`), зона захвата **10 px** (`cursor: col-resize`), при наведении подсвечивается `var(--accent)` — как сейчас у `.colResizer`, это работает, оставляем.
- `pointerdown` → `setPointerCapture`, `body.resizing`, оверлей на весь экран (ловит курсор при быстром движении).
- `pointermove` → новое значение = `clamp(start ± dx, min, max)`, где `min = 180` (полоса) / `120` (док), `max = min(45% окна, 460)`.
- `pointerup` → сохранение, `sizes.left.auto = false`.
- Двойной клик по ручке — вернуть авто-значение для этой панели (`auto = true`).
- Курсор и хит-зона одинаковы для всех трёх ручек; на тач-устройствах зона 16 px.

### 4.5 Клавиатура

Ручка — `<div role="separator" tabindex="0" aria-orientation="vertical" aria-valuenow="248" aria-valuemin="180" aria-valuemax="460" aria-label="Ширина левой панели">`.

| Клавиши | Действие |
|---|---|
| `←` / `→` | ±16 px |
| `Shift + ←/→` | ±48 px |
| `Home` / `End` | минимум / максимум |
| `Enter` | вернуть авто |

`aria-valuenow` обновляется на `pointerup` и на каждое нажатие клавиши (не в `pointermove` — иначе скринридер захлёбывается).

### 4.6 Приоритет ручного и авто

- `auto: true` — значение пересчитывается при каждом `resize` по §4.1.
- `auto: false` — значение фиксировано, но **зажимается** в `[min, 45%]` при сужении окна; если окно стало меньше суммы минимумов — панели принудительно сворачиваются в иконки, а не вылезают за экран.
- Кнопка «Сбросить размеры» возвращает все три в `auto: true`.
- Индикатор в настройках: «Левая панель: 248 px (авто)» / «(вручную)».

### 4.7 Масштаб текста и DPI

- Все размеры — в `rem` от `--fs-base` (15 / 17 / 19 px, текущие `body.bigFont/.hugeFont` сохраняются как переключатель).
- Брейкпоинты считаются в CSS-пикселях, поэтому на 4K при масштабе Windows 200% окно видит 1920 CSS-px и попадает в строку «1920–2559» — это правильно, не надо ничего умножать.
- При 3840 без масштабирования шрифт 15 px физически мелкий — на ширине ≥2560 `--fs-base` поднимается до 16, на ≥3200 — до 17, если пользователь не выбрал вручную.
- Минимальный физический размер интерактивного элемента — 32×32 CSS-px (сейчас `button.tiny` — 24,6).

### 7.3 Реестр блоков

```js
var REGISTRY = {
  model: { title: 'Модель', minW: 240, defH: 190, lane: 'right', render: renderModelBlock, update: updateModelBlock },
  chats: { title: 'Чаты',  minW: 200, defH: 0,   lane: 'left',  render: renderChatsBlock, update: updateChatsBlock },
  /* ... 14 записей ... */
};

function mount(id, container) {
  var node = NODES[id] || (NODES[id] = buildBlock(id));   // один узел на блок
  if (node.parentNode === container) return;
  var scroll = node.querySelector('.blk-body');
  var top = scroll ? scroll.scrollTop : 0;
  container.appendChild(node);                             // перенос, не копия
  if (scroll) scroll.scrollTop = top;                      // scrollTop не гарантирован
}
```

`buildBlock(id)` создаёт:

```html
<section class="blk" data-blk="model" aria-labelledby="blk-model-h">
  <header class="blk-head">
    <button class="blk-grip" aria-label="Переместить блок Модель">⠿</button>
    <h3 id="blk-model-h">Модель</h3>

  </header>
  <div class="blk-body" id="blk-model-body"><!-- контент --></div>
</section>
```

Требование: `document.querySelectorAll('[data-blk="model"]').length === 1` в любой момент. Отладочная проверка в `layout.js` при `mount` — если 2, кидаем в консоль и не монтируем.

### 7.4 Перетаскивание: скелет

```js
function onGripDown(e) {
  var blk = e.target.closest('.blk');
  var start = { x: e.clientX, y: e.clientY };
  var moved = false;
  blk.setPointerCapture(e.pointerId);

  function move(ev) {
    if (!moved && Math.hypot(ev.clientX - start.x, ev.clientY - start.y) < 4) return;
    if (!moved) { moved = true; startDrag(blk); }
    positionGhost(ev.clientX, ev.clientY);
    showInsertMark(laneAt(ev.clientX, ev.clientY), ev.clientY);
    autoScroll(ev.clientY);
  }
  function up(ev) {
    blk.releasePointerCapture(e.pointerId);
    blk.removeEventListener('pointermove', move);
    blk.removeEventListener('pointerup', up);
    if (moved) commitDrop(blk, ev); else toggleFold(blk);
  }
  blk.addEventListener('pointermove', move);
  blk.addEventListener('pointerup', up);
}
```

`positionGhost` и `showInsertMark` пишут только `transform` и `top` — это композитинг, без layout. `autoScroll` — один `scrollTop += 8` за кадр через `requestAnimationFrame`, не в `pointermove` напрямую (иначе 120 событий/с).

`commitDrop`:

1. `before = new Map()` — `getBoundingClientRect()` всех блоков целевой полосы (одна пассивная читка).
2. `insertBefore(node, ref)`.
3. `after` — те же rects.
4. FLIP: `transform: translateY(before.top - after.top)`, затем `requestAnimationFrame` → `transition: transform 160ms` → снять.
5. `saveLayout()` с дебаунсом 250 мс.

### 7.5 Ручки: скелет

```js
function wireSeparator(el, side) {
  el.addEventListener('pointerdown', function (e) {
    e.preventDefault();
    el.setPointerCapture(e.pointerId);
    var startX = e.clientX, startW = currentWidth(side);
    document.body.classList.add('resizing');
    function move(ev) {
      var d = side === 'left' ? ev.clientX - startX : startX - ev.clientX;
      var w = clamp(startW + d, MIN[side], Math.min(innerWidth * 0.45, MAX[side]));
      root.style.setProperty(side === 'left' ? '--rail-left' : '--rail-right', w + 'px');
    }
    function up() {
      el.removeEventListener('pointermove', move);
      el.removeEventListener('pointerup', up);
      document.body.classList.remove('resizing');
      el.setAttribute('aria-valuenow', String(currentWidth(side)));
      saveLayout({ sizes: { [side]: { px: currentWidth(side), auto: false } } });
    }
    el.addEventListener('pointermove', move);
    el.addEventListener('pointerup', up);
  });
}
```

### 7.6 Обновление данных

Три уровня частоты, вместо одного общего таймера:

| Данные | Частота | Когда | Механизм |
|---|---|---|---|
| Статус (фаза, токены, скорость) | 2 с | вкладка видима | `/api/stats`, diff по `textContent` |
| Ресурсы (ЦП/ОЗУ/диск) | 2 с | блок в полосе и виден | `/api/stats`, те же данные |
| Модель, чаты, проекты, задачи | по событию | после действия | `loadState()` |
| Логи | 1 с | док открыт и видим | `/api/stats.activity` |
| Таймер «Сейчас» | 1 с | блок `now` виден и активен | локальный счётчик, без сети |

Правила:

- `document.hidden` → все таймеры на паузу (`visibilitychange`).
- `dragActive` → тик пропускается.
- Один запрос `/api/stats` на тик, не три (сейчас `/api/stats`, `/api/panels`, `/api/state` каждые 1,5 с — `loadState` внутри `Panels.refresh`).
- Обновление — `el.textContent = value` только если `el.textContent !== value`. Для чисел — сравнение с предыдущим значением в замыкании.
- Никакого `innerHTML` в цикле обновления. `innerHTML` — только при первичном рендере блока.

### 7.7 Доступность: чек-лист

- [ ] Все интерактивные элементы — `<button>`, не `<div onclick>` (сейчас 3 inline-обработчика в `index.html` и 19 в строках, собираемых `app.js`).
- [ ] `:focus-visible` — обводка 2 px `var(--accent)`, `outline-offset: 2px`; сейчас фокус виден только у `textarea`.
- [ ] Порядок табуляции: шапка → левая полоса → центр → правая → док → статус. Достигается порядком в DOM; при перетаскивании блоков порядок меняется вместе с ними — это ожидаемо.
- [ ] Ручки — `role="separator"` + `aria-valuenow/min/max` + клавиатура (§4.5).
- [ ] Блоки — `aria-labelledby`, сворачивание — `aria-expanded`.
- [ ] Перемещение — `aria-live="polite"`, одно объявление на действие.
- [ ] Подсказки `?` — `aria-describedby`, показ по фокусу и наведению (задержка 400 мс), `Esc` закрывает, `position: fixed` с переворотом, чтобы не обрезались.
- [ ] Модалки — `role="dialog" aria-modal="true"`, ловушка фокуса, возврат фокуса на кнопку-источник.
- [ ] `prefers-reduced-motion` — отключить FLIP и pulse-анимацию точки.
- [ ] Контраст ≥4,5:1 для текста <18 px; заменить `#5f6b7d` (3,5:1) на `#7d8798` (5,2:1).
- [ ] Минимальная цель 32×32 (сейчас `button.tiny` 24,6, `.chip` 27,4).
- [ ] Иконки-эмодзи (`📎`, `🎤`, `⚙`) — с `aria-label`, иначе скринридер читает «скрепка».

| Запросов в простое | 3 / 1,5 с = 2/с | 1 / 2 с = 0,5/с |
| `innerHTML`-перезаписей за тик | 16 (7 статус + 4 метрики + 5 панели) | 0 |
| DOM-записей за тик | ~30 | ≤ 6 (и только изменившиеся) |
| Перерисовок при перетаскивании | — | 1 style-write на кадр, ≤ 2 reflow на drop |
| Перерисовок при ресайзе окна | — | 1 на кадр (rAF), ≤ 3 reflow |
| Переключение вкладки | полный рендер секции | ≤ 30 мс, `content-visibility: auto` для неактивных |
| Память | 2 копии данных в `STATE`/`STATS` | без изменений |

Приёмы: `contain: layout style paint` на `.blk`, `content-visibility: auto` + `contain-intrinsic-size: 200px` на неактивных `.view`, `will-change: transform` только на призраке и только на время перетаскивания (иначе — лишние слои).

### 7.9 Этапы внедрения

|---|---|---|---|

## 8. Риски и что сломается

| # | Риск | Причина | Симптом | Митигация |
|---|---|---|---|---|
| R1 | Вертикальный бюджет не сойдётся | шапка 62 → 48, строка модели и подсказка убираются | если сделать только шапку, лента вырастет на 14 px, а расчёт §2.2 (536) не сойдётся | шаги 1–2 одним коммитом, сверка с таблицей §2.2 на 5 разрешениях |
| R2 | Перерисовка блока под курсором | `panels.js:691` пишет `innerHTML` каждые 1,5 с | призрак отрывается, блок «мигает» | `dragActive` + шаг 7 до шага 5 |
| R3 | Два экземпляра блока | кто-то скопировал разметку вместо `mount()` | дубли id, `getElementById` возвращает первый, второй мёртв | проверка в `mount()`, ревью: в HTML блоков нет |
| R4 | Потеря ввода в `tuning` | `renderTuning` пересобирает `<select>` | текст стирается, фокус уходит | обновлять только `value`, не `innerHTML` |
| R5 | Старая раскладка ломает вид | в `localStorage` ключи `agentAccState`, `agentDrawerWidths` | все блоки свёрнуты/ширины 0 | миграция по подписям, `v:2`, неизвестные id игнорируются |
| R6 | Пропавшие настройки из модалки ⚙ | модалка удаляется | пользователь ищет «Проверить обновления» | перенести 1:1 в «Настройки → Приложение», в ⚙ оставить ссылку-переход |
| R7 | Кэш service worker | `CACHE = 'localagent-v2'` | после обновления старый CSS | network-first уже есть; поднять до `v3` при смене списка `SHELL` |
| R8 | Прокрутка чата после переноса узла | `#messages` переезжает в `.center` | чат открывается в середине/вверху | сохранять `scrollTop` при `mount`, `scrollDown()` после |
| R9 | Сетка ломается длинными путями | `1fr` без `minmax(0,…)` | колонка распирает экран, появляется горизонтальный скролл | везде `minmax(0,1fr)` + `overflow-wrap: anywhere` для путей |
| R10 | Сенсорный ввод (телефон по LAN) | `pointerdown` без `touch-action` | страница скроллится вместо перетаскивания | `touch-action: none` на `.blk-grip`, зона 44 px |
| R11 | Клавиатурные пользователи | drag только мышью | функция недоступна | меню «Переместить в…» (§3.4) — обязательный пункт приёмки |
| R12 | Тесты | `tests/*.py` не ссылаются на UI-id (проверено), но smoke-тесты поднимают сервер | падение при смене разметки маловероятно | прогон `tests/smoke_*.py` после шага 3 |
| R13 | 4K без масштабирования | 15 px шрифт физически мелкий | «всё мелкое» | `--fs-base` 16–17 на ≥2560 |
| R14 | Печать/скриншоты | фиксированные панели | в печать уйдёт интерфейс | `@media print { .rail, .dock, .statusbar { display: none } }` |

Отдельно: **не переносить** в блоки то, что требует полной ширины — таблицу ролей, трёхколоночную базу знаний, сетку моделей. Эти вещи живут в центре, а полосы дают к ним быстрый доступ (список, счётчик, поиск).

## 9. Приёмка

Проверяется на 1366×768, 1440×900, 1920×1080, 2560×1440, 3840×2160, а также в окне 880×900 и 1024×600.

**Раскладка**

- [ ] Шапка ровно 48 px, ничего не обрезано, логотип в одну строку на всех разрешениях.
- [ ] На 1366 сообщений видно ≥500 px при закрытом доке и ≥330 при открытом.
- [ ] Центр на 1920 — ≥1280 px, на 2560 — ≥1880 px.
- [ ] Ни на одном разрешении нет горизонтальной прокрутки `body`.
- [ ] Каждый блок существует в одном экземпляре (`querySelectorAll('[data-blk=X]').length === 1`).

**Kanban**

- [ ] Блок перетаскивается в любую из трёх полос и на склад; после F5 — там же.
- [ ] Перетаскивание работает с клавиатуры без мыши.
- [ ] Нельзя положить 7-й блок в полосу; сообщение понятное.
- [ ] `Esc` во время перетаскивания возвращает блок.
- [ ] «По умолчанию» возвращает исходную раскладку за один клик.

**Размеры**

- [ ] Изменение размера окна пересчитывает полосы по таблице §4.1 без «прыжков».
- [ ] Ручная ширина сохраняется и зажимается в границы при сужении.
- [ ] Ручка работает стрелками, `aria-valuenow` меняется.
- [ ] Двойной клик по ручке возвращает авто.

**Данные**

- [ ] В простое — 1 запрос в 2 с, 0 `innerHTML`.
- [ ] Ввод в «Контекст → своё значение» не стирается.
- [ ] При скрытой вкладке браузера запросов нет.
- [ ] Во время перетаскивания блоки не перерисовываются.

**Доступность**

- [ ] Все цели ≥32×32.
- [ ] Контраст мелкого текста ≥4,5:1.
- [ ] Подсказка `?` не обрезается у краёв, закрывается `Esc`, читается скринридером.
- [ ] Модалки держат фокус и возвращают его.
- [ ] Полный проход по интерфейсу только с клавиатуры.
