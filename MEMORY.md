# Память проекта «Локальный агент»

Файл читается в начале сессии и обновляется в конце. Четыре уровня — от самого
устойчивого к самому свежему. Правило: **L1 меняется редко, L2 — при изменении
архитектуры, L3 — при каждом решении или найденной [PERSON_NAME], L4 — каждый рабочий заход.**

---

## L1. Паспорт проекта

| Параметр | Значение |
|---|---|
Что это | Локальный ИИ-агент для Windows: чат, инструменты, роли, знания, голос. Без облака |
Где лежит | `C:\Users\volko\LocalAgent` |
Данные | `%LOCALAPPDATA%\LocalAgent` (или `data\` рядом с программой в портативном режиме) |
Стек | Python 3.11+, только стандартная библиотека. Без Electron, без pip-зависимостей |
Запуск | `python run.py` (или `start.bat`), UI на `[IP_ADDRESS]:7867` |
Авторизация | токен в `access.token`, заголовок `X-Agent-Token` |
Движки | внешние: `llama-server` (llama.cpp), `whisper-cli` (whisper.cpp) |
Модель по умолчанию | Qwen3-4B-Instruct-2507 Q4_K_M, ~2.5 ГБ |
Портативная сборка | `python build_portable.py` → `dist\LocalAgent` (~21 МБ) |
Тесты | `tests\smoke_*.py`, запуск: `python tests\smoke_rag.py` и т.д. |
Репозиторий | git, ветка `main`, коммиты по завершённым спринтам |

## L3. Решения и грабли

- **Только stdlib.** Никаких pip-зависимостей: сборка должна запускаться на чистой Windows.
- **Слушаем `[IP_ADDRESS]`, а не `localhost`.** [PERSON_NAME] сначала пробует IPv6 и ждёт 2 с — из-за этого весь интерфейс тормозил (замер: 2.35 → 0.067 с).
- **`/api/state` кэшируется** (модели 5 с, GPU 60 с): скан диска и PowerShell-опрос стоят ~270 мс.
- **FTS5 после вставки требует `rebuild`.** Простое `INSERT` в таблицу с `content=` индекс не строит — поиск возвращал 0.
- **Токен обязателен на всех `/api/*`.** Свои скрипты шлют `X-Agent-Token`, иначе 401.
- **Опасные инструменты** (`write_file`, `run_command`) идут через `approval_gate`: окно в UI, отказ уходит агенту как отказ.
- **Портативность через маркер `portable.txt`** рядом с `run.py` — тогда данные в `data\`.
- **Пересборка портатива не стирает данные:** удаляется только `app\`, `data\` и `models\` остаются.
- **Ключи API — только DPAPI**, в `settings.json` их нет и в `/api/state` они не отдаются.
- **Голос:** турбо-модель + `-bs 5` + `--prompt` со словарём; распознанное сначала попадает в поле ввода, не в чат.
- **Осторожно с автозаменой текста в инструментах.** Иногда русские фразы в коде заменяются маркерами — после правок проверять `py_compile`, `node --check` и искать `[PERSON_NAME]`/`[ADDRESS]` по файлам.

---

- **Эмбеддинги — отдельный сервер.** `llama-server` с `--embeddings` на чат-модели отдаёт векторы длины 1: у чат-модели нет эмбеддинговой головы. Правильно: второй процесс на своём порту (с 8190) с моделью эмбеддингов, чат-сервер не трогаем.
- **Только `/v1/embeddings`.** Нативный `/embeddings` в llama.cpp возвращает список без ключа `data`, а OpenAI-совместимый путь даёт `data[].embedding` и умеет батч.
- **nomic-embed-text — английский.** На русских фразах близость у всех пар ~0.76; для русского нужен bge-m3 или embeddinggemma (проверено: 0.935 у похожих и 0.60 у разных).
- **Тип вектора хранится рядом.** В `chunks` есть `vec_kind`: `sem` или `hash`. Поиск сравнивает только векторы того же типа, иначе хеш-векторы дают мусор.
- **Пересчёт базы идёт по одному документу.** `reindex` удаляет и заново индексирует каждый источник, а не чистит базу целиком: прерывание не теряет данные.
- **HF API:** `GET /api/models?search=<q>&filter=gguf&sort=downloads&direction=-1` и `/api/models/<repo>/tree/main` для файлов. Имя репозитория проверять регуляркой `автор/имя`, имя файла — только `.gguf` без путей.

---

- **Гибридный поиск по RRF.** BM25 и векторы считаются всегда, выдача сливается по 1/(60+место): не бывает «или слова, или смысл», в выдаче есть поле `source`.
- **Батч эмбеддингов не ускоряет.** Замер: 12 текстов одним запросом 2.03 с против 0.94 с поштучно; `-np 4` ускоряет только параллельные вызовы (6.5 с против 25.4 с), зато одиночный делает в 25 раз медленнее. Поэтому индексируем по фрагменту на обычном сервере (порт 8190, `-c 2048`).
- **Префиксы — по имени модели.** nomic и e5 без префикса работают хуже, поэтому в `PREFIX` они есть; embeddinggemma без префикса даёт больший отрыв (0.135 против 0.126) и в словаре её нет.
- **HF-токен удаляется пустой строкой** — `keystore.drop("hf_token")`, а не ошибка «пустой токен».

---

- **Сервер эмбеддингов пишет `embed.pid`.** При старте приложение гасит сироту из прошлого запуска: после падения иначе остаются `llama-server` на 819x по ~860 МБ памяти.
- **Фоновые задачи вместо ожидания.** `/api/model/load` с `background`, `/api/update/apply` через `_start_job` (флаг `wait` оставлен для скриптов), UI опрашивает `/api/jobs` через `waitJob`. Синхронный вызов висел 10–60 с.
- **Подпись манифеста — ECDSA P-256 в Windows CNG.** Сторонние библиотеки не нужны: `BCryptImportKeyPair` + `BCryptVerifySignature`, подписываем строку `version\nurl\nsha256`. Ключ в настройках `update_pubkey`; без ключа подпись не проверяется, но sha256 обязателен всегда.
- **`config.save` игнорирует ключи вне DEFAULTS.** Так молча не сохранялся `telegram_chat` — любой новый параметр сначала добавлять в `DEFAULTS`.
- **Пустой файл и пустое имя вложения — отказ.** `save_upload` подставлял имя `file` и писал нулевой файл; теперь оба случая дают понятную ошибку.

---

- **Диск моделей может отключиться.** 2026-11-20 пропал `F:` — `models_dir` недоступен, эмбеддинги не работают, поиск остаётся на BM25. В `embed.status` есть `dir_ok` и `dir`, в «Знаниях» показывается предупреждение вместо тихого «выключено».
- **Подсказка о перетаскивании не занимает место.** `#dropHint` скрыт по умолчанию, появляется на 6 секунд при клике 📎 или при перетаскивании. Кнопка 📎 открывает выбор файла — раньше прикрепить файл можно было только перетаскиванием.
- **`wireDrop()` был объявлен, но не вызывался.** Перетаскивание файлов не работало вовсе; теперь в `bootStep` есть `drop` и `attach`. Любую `wire*`-функцию проверять по вызовам, а не по наличию.

---

- **Модель выбирается у поля ввода.** Над композером `.modelRow`: список `.gguf` с размером, кнопки «Загрузить» и «Выгрузить»; верхняя полоса `chatBar` удалена, путь и занятая память живут только внизу — в статусе и в шторке «Панели».
- **`last_model` не должен указывать на embedding-модель.** Скачивание HF больше не пишет её в `last_model`, а панель и выбор модели пропускают файлы со `embed` в имени.

---

- **Скины и темы — только через переменные.** Любой жёсткий цвет (`#1b2740`, `#0d1017`, `#5f6b7d`) ломает светлую тему: тёмный текст на тёмном фоне. Все служебные цвета — в палитре, проверка `python tests/check_contrast.py` (6 палитр, порог 4.5/3.0).
- **Имена классов не должны пересекаться.** `.bar` был и шапкой, и полосой прогресса: шапка сжалась до 25 px и покрасилась в цвет дорожки. Прогресс переименован в `.meter`.
- **`lan_access` меняет привязку сервера только при старте** (0.0.0.0 вместо 127.0.0.1), поэтому после переключения нужен перезапуск приложения.
- **Плотность и размер текста — тоже переменные** (`--fs`, `--pad-view`, `--row-pad`, `--card-pad`, `--gap`), иначе `body.bigFont` и «компактно» спорят за `font-size`.

---

- **Вектор помечается моделью.** `vec_kind = "sem:<имя модели>"`; поиск сравнивает только векторы той же модели. Иначе смена модели эмбеддингов тихо ломает ранжирование. После смены модели — «Пересчитать базу».
- **Батч эмбеддинг-сервера — 2048.** По умолчанию физический батч 512, и фрагменты длиннее ~510 токенов валятся с HTTP 500 (`input is too large`), а `rag` молча писал их хеш-векторами. В `engine.start_embed` теперь `-b 2048 -ub 2048`, в `rag.embed` — повторная попытка перед запасным хешем.
- **`lan_access`: мало слушать `0.0.0.0`.** Проверка `_host_ok` должна пропускать приватные адреса (`ipaddress.is_private`), иначе телефон получает 403, хотя порт открыт.

---
- **Раскладка — это данные, а не разметка.** Блоки `.kblock[data-block]` живут в пяти зонах `[data-zone]` (`left`, `right`, `drawer1…3`); место и порядок — в `localStorage.agentLayout.v2`, схлопывание — в `agentBlocksCollapsed`. Новая панель = новый `.kblock` в любой зоне: перетаскивание, сохранение и сброс работают сразу.
- **Зона — на `.railBody`, не на `<aside>`.** Иначе в зону попадают заголовок панели и `saveLayout` теряет блоки (сохранялись пустые списки).
- **Индексы в тексте считаются заново после каждой замены.** Вставка шторки по индексам, снятым до замены чата, уехала внутрь вкладки «Настройки» и разорвала разметку.
- **Шторка — flex-колонка.** `.drawer.open { display:flex; flex-direction:column }` и `.drawerGrid { flex:1; min-height:0 }`; без этого колонки растягиваются по содержимому и `overflow:hidden` режет блоки без прокрутки.

---
- **Блоки мониторов обновляются на месте.** `patchBox(box, html)` сверяет форму строк и меняет только текст и ширину полоски: пересборка `innerHTML` каждые 1.5 с сбрасывала `transition` и полоски «пульсировали», а блок дёргался.
- **Один хозяин на блок.** `renderStats` писал в `monRes`, `monModel`, `monNow`, и `Panels.renderAll` — тоже; два рендера перезаписывали друг друга. Теперь мониторы — только `panels.js`, `renderStats` — только «Токены и скорость».
- **`scrollbar-gutter: stable`** на `.railBody` и `.drawerCol`: появление полосы прокрутки сужало блок на 10 px и сдвигало всю панель.
- **`tabular-nums` + `flex-wrap` у `.metric`**: цифры не «дышат» по ширине, длинное значение переносится на свою строку, подпись не режется.

---
- **«Роли» в панели — справочник, а не навигация.** Клик по блоку больше не уводит на вкладку: «Список ролей» раскрывает перечень с подсказкой при наведении (думает, инструменты, описание), клик по строке закрепляет полное описание, Esc или клик вне — закрывает. Переход на вкладку «Команда» — только по шестерёнке в заголовке блока.
- **Подсказка живёт в слое на `body`, а не в блоке.** `.railBody` и `.drawerCol` прокручиваются (`overflow-y: auto`), поэтому абсолютная подсказка внутри обрезалась бы по краю панели. `#tipLayer` — `position: fixed`, прижимается к правому краю строки и переворачивается у края окна.

---
- **Режимы работы живут в строке модели.** «Один» и «Команда» (полные подписи — в `title` и «?») стоят справа в `.modelRow`, а не отдельной строкой; `applyMode` их не трогает, `flex-wrap: nowrap` держит одну строку до 1000 px, ниже — перенос.
- **Селект модели сжимается, а не давит строку.** `.modelPick { flex: 1 1 220px; min-width: 120px; max-width: 420px }`; подпись модели (`#modelHint`) усекается многоточием, поэтому строка модели остаётся 40 px.
- **Примеры ТЗ — чипы 24 px.** `.chip` уменьшены до `font-size: 11.5px; padding: 2px 9px; min-height: 24px`, строка шаблонов 26 px вместо 38. Вместе с переносом режимов это вернуло чату 63 px (349 → 412 при 1440×900).

---
- **Зрение — это проектор, а не модель.** `engine.find_projector(path)` ищет `mmproj*.gguf` в папке модели и передаёт `--mmproj`; поэтому любая VL-модель работает и как основная, и в отдельном слоте. Привязки к имени модели нет.
- **Второй слот — только когда нужен.** Если у основной модели есть проектор, картинки идут в неё (с инструментами). Если нет — поднимается `app/vision.py`: свой `llama-server`, свой порт 8300+, свой pid-файл, чат-модель не загружается вообще. Маршрут решается в `_stream_chat` до `engine.start`.
- **Признак зрения в имени решает порядок выбора.** Кандидаты сортируются так: сначала модели с `-vl`/`vision`/`llava`/`gemma-3`, затем по размеру. Файлы-черновики (`dflash`, `draft`, `eagle`, `lora`, `adapter`) и всё мельче 1,5 ГБ отбрасываются — иначе «самая лёгкая» оказывается спекулятивным драфтом без проектора.
- **Картинки уходят как `image_url` с data URL.** `agent._with_images` превращает поле `images` сообщения в части контента; работает и с llama.cpp, и с внешними OpenAI-совместимыми провайдерами. Ответ по картинке идёт через `chat_plain` — без инструментов, чтобы маленькая VL-модель не пыталась вызывать функции.
- **`images` не попадает в историю.** `agent._clean` вырезает служебное поле из события `done`, иначе при следующей отправке старые картинки уходили бы повторно.
- **Служебные события `note`** показываются строкой в чате до ответа: «Загружаю модель зрения…», «Картинки разбирает …».

---
- **Слова задачи надёжнее эмбеддингов.** `tools.select` сначала ищет теги в тексте задачи, и только потом добавляет не больше одного инструмента по смыслу (порог 0,76 или близко к лучшему). На замерах «привет, как дела?» давал до 8 инструментов по чистой близости — модель эмбеддингов ставит 0,66–0,85 почти всему.
- **`_only_tools` — единственный механизм сужения.** `agent._prepare_tools` вычисляет набор один раз на запрос, пишет его в `cfg["_only_tools"]` и отправляет событие `note` со списком. `tools.schemas` не знает про авто — просто уважает `_only_tools` и `tools_off`.
- **MCP подключается к задаче, а не к любому вопросу.** `mcp` в набор добавляется, только если уже выбраны встроенные инструменты или задача длиннее 25 символов; иначе на «привет» уходило 12 схем демо-сервера.
- **`npx` на Windows — это `.cmd`.** `subprocess.Popen(["npx", ...])` падает с `WinError 2`; `mcp._argv` разворачивает через `shutil.which` и запускает `.cmd`/`.bat` как `cmd.exe /c <путь> <аргументы>`.
- **`mcp.call` поднимает сессию сам.** Иначе вызов инструмента первым (без предварительного `tools_for`) отвечал «сервер не запущен».
- **Дубли `elif` в `do_POST` съедают запрос.** Два блока `/api/mcp/add` (и `/api/mcp/test`) — первый делал только проверку разрешения и не отвечал, второй не выполнялся: клиент получал пустой ответ. Один маршрут — один `elif`.
- **Явное действие пользователя — уже согласие.** Кнопки «Подключить»/«Проверить» в каталоге не проходят `approval_gate`; подтверждение остаётся для записи файлов и команд.

---
- **`start_embed` гасит сервер прошлого запуска.** `embed_cleanup()` вызывается и внутри запуска, иначе тесты и перезапуски копили по одному `llama-server` (7 штук, 7,6 ГБ) на портах 8190+.
