# UI_RESEARCH: как устроены рабочие пространства у локальных LLM-приложений и Kanban-досок

Дата: 22.11.2026 · Для проекта «Локальный агент» (офлайн, Windows, один пользователь, слабая встроенная графика, Python stdlib + ванильный JS).

Цель: выбрать компоновку панелей, место выбора/загрузки модели, поведение на узких окнах и правила Kanban — на основе того, как это сделано у других.

**Обозначения источников** (важно: где я видел, а где предполагаю):

- **[Д]** — официальная документация продукта (страница открыта, текст прочитан).
- **[К]** — исходный код продукта (файл скачан, строка проверена).
- **[С]** — видел сам на скриншоте (смотрел изображение).
- **[3]** — сторонний источник (статья, замер).
- **[П]** — предположение / не проверено; требует проверки вживую.

## 2. Разбор по продуктам

### 2.1. LM Studio — самый близкий аналог по задачам

Компоновка (видел на аннотированном скриншоте [С] + доки [Д]):

- Слева одна колонка с иконкой и подписью: **Chat, Model Server, Library, LM Link, Model Search**; под меню — список чатов с поиском, «New Folder» и папками (ширину в пикселях не замерял).
- Верхняя панель чата: **пикер модели** (в скриншоте — «MLX google/gemma-4-e4b»), рядом **Eject** (выгрузить из памяти), справа — split view, загрузки, тоггл правой панели.
- Правая панель — две вкладки: **Integrations** (плагины, MCP) и **Model Parameters** (system prompt, temperature).
- Внизу композер с чипами инструментов (Think, Vision, Chat with Files, Code Interpreter) и индикатором заполнения контекста «15%».
- Горячие клавиши: `Ctrl/Cmd+N` — новый чат, `Ctrl/Cmd+Shift+N` — новая папка [Д].
- Перетаскивание: чаты и папки друг в друга, split view перетаскиванием вкладки в половину окна [Д].

**Что взять:** пару «модель + выгрузить» в одном месте; чипы инструментов в композере; процент контекста; правую панель параметров.
**Что не брать:** модель одновременно в трёх местах (пикер, Library, Model Parameters) — см. антипаттерны.

### 2.2. Jan

- Левый сайдбар: треды, ассистенты, **Hub** (скачивание моделей) [Д].
- Модель переключается в любом чате, в том числе посреди треда; настройки треда — **в правой панели** [Д].
- В коде поле ввода импортирует `ComposerModelPicker` — то есть выбор модели живёт в композере [К].
- Ширина левой панели по умолчанию — `'15rem'` (=240px при 16px базовом шрифте), хранится в сторе как строка [К].

**Что взять:** 240px как нижняя граница «нормального» сайдбара; параметры — в правую панель, а не в модалку.
**Минус:** скачивание модели (Hub) и выбор модели (композер) — разные места; новичок ищет модель там, где чат.

### 2.3. Open WebUI — лучший документированный пример миграции контрола

- До v0.11 выбор модели был **в шапке**, с v0.11 — **внутри поля ввода**. Формулировка из релизного блога: «Your model choice is part of the message you're about to send, so it belongs with the message, not in the page chrome above it» [Д].
- Там же: `@` в поле ввода ищет модели, папки, базы знаний и файлы; `/compact`, `/fork`, `/status` — слэш-команды; горячие клавиши стали переназначаемыми (раздел Keyboard в настройках); наведение на чат показывает превью последних сообщений [Д].
- Сайдбар: 6 групп, у Folders/Notes/Channels — кнопка «+» в заголовке группы; один общий компонент секции, чтобы поведение было одинаковым [Д].
- Числа из исходников [К]: `MIN_WIDTH = 220`, `MAX_WIDTH = 480`, стартовая ширина **245px**, иконочный рейл `w-[42px]`, на мобильном ширина = `min(380, viewportWidth - 40)`, брейкпоинт `BREAKPOINT = 768`.
- Ширина сайдбара сохраняется в `localStorage` и пишется в CSS-переменную `--sidebar-width` [К].

**Что взять:** модель — в композер; `@` как единый способ прикрепить файл/базу; числа 220/245/480; брейкпоинт 768.
**Осторожно:** `localStorage` для раскладки — у нас портативное приложение, профиль WebView может пересоздаваться; хранить в `data/config.json` (см. §5.7).

### 2.4. AnythingLLM

- Модель выбирается не в чате, а в настройках, и имеет **три уровня**: System LLM (по умолчанию), Workspace LLM (переопределяет для конкретного воркспейса), Agent LLM (для агента) [Д].
- Сайдбар: 292px в открытом состоянии, внутренняя колонка `min-w-[250px]`; поддержано скрытие сайдбара [К].
- Знания привязаны к воркспейсу — это ближайший аналог нашей «базы знаний».

**Что взять:** идею «модель по умолчанию + переопределение на уровне пространства» (у нас — на уровне роли/задачи).
**Минус:** в самом чате нет индикатора, какой моделью отвечают — приходится помнить настройки [П, по докам не видно обратного].

### 2.5. Msty / Msty Studio

- Сайдбар двухзонный: сверху чаты и проекты + **переключатель воркспейсов** и ресайз-разделитель; снизу — иконки: Knowledge Stacks, Prompts, Turnstiles, Skills, Personas, Context Studio, Toolbox, Settings [Д].
- **Пункты нижней зоны можно перетаскивать (порядок) и скрывать** [Д]. Это редкая и полезная возможность: у пользователя 6+ разделов, и он сам решает, какие видны.
- Пикер модели: закрепление часто используемых, категории Text / Embedding / Vision / Coding [Д].
- Split-chat: один промпт в несколько моделей или разные треды рядом [Д].

**Что взять:** двухзонный сайдбар (список сверху, иконки разделов снизу) + настраиваемый порядок/скрытие пунктов; закрепление моделей.
**Минус:** обилие сущностей (Turnstiles, Skills, Personas, Context Studio) — для одного пользователя это перегруз; у нас разделов должно быть ≤6.

### 2.6. GPT4All

- Меню слева: Home, Chats, Models (+ LocalDocs) [Д].
- Модель — **дропдаун в шапке страницы Chats**, загрузка — «Load Default Model» [Д].
- История чатов — кнопка в левом верхнем углу, панель LocalDocs — кнопка в правом верхнем углу [Д].

**Что взять:** LocalDocs как выдвижная панель поверх чата (не отдельная вкладка) — дешево по вниманию.
**Минус:** три управляющих элемента в трёх углах шапки.

### 2.7. Chatbox (типовой GUI для Ollama)

- Сайдбар: новый чат, поиск, генерация картинок, My Copilots; список **Pinned / Projects / Chats**; внизу Settings, Help, About [Д].
- В поле ввода: вложения, переключатель **Chat Mode / Work Mode** (там же веб-поиск, базы знаний, инструменты), настройки беседы и **выбор модели** [Д].

**Что взять:** группировка списка «закреплённые → проекты → остальные»; переключатель режима в композере.
**Про Ollama GUI:** отдельного полноценного десктоп-GUI у Ollama нет, Ollama App — минимальное окно/трей, поэтому как «GUI» рассматриваем Chatbox и Open WebUI [П, не проверял текущую версию Ollama App].

### 2.8. KoboldCpp

- Загрузка модели и все параметры сервера — в **отдельном окне-лаунчере**: колонка вкладок слева, настройки активной вкладки справа [Д].
- Веб-UI (KoboldAI Lite) — отдельная сущность: верхнее меню Settings с вкладками General / GUI / Samplers / Media / Tokens / Tools / Misc; блок **Context** (memory, world info, author's note) — **над полем ввода** [Д].
- Разделение обязанностей сформулировано в доках явно: «лаунчер решает, что может сервер; Lite решает, что отправляется с каждым запросом» [Д].

**Что взять:** контекст/память компактным блоком над вводом (у нас это «знания» и «инструменты»).
**Минус:** два окна и семь вкладок настроек — для одного пользователя лишний шаг.

### 2.9. Оболочки: VS Code, Obsidian, JetBrains

**VS Code** — эталон чисел и свободы раскладки [К][Д]:

- Activity Bar 48px, компактный 36px, «плавающий» 36/28px.
- Primary Sidebar 300px, Secondary Sidebar 300px, Panel 300px, Status Bar 22px.
- Стартовая ширина сайдбара адаптивная: `Math.min(300, ширина_контейнера / 4)` — на окне 1000px это 250px.
- Панель можно переносить влево/вправо/вниз/вверх; вью и панели перетаскиваются мышью **и** командами `View: Move View` (клавиатурой).
- Вторичный сайдбар — `Ctrl+Alt+B`; он всегда напротив основного.
- У чата (Copilot) ширина по умолчанию — **30% ширины окна** (`CHAT_PART_DEFAULT_WIDTH_RATIO = 0.3`).

**Obsidian** [Д]:

- Два сайдбара, каждый — стек вкладок с иконками; Ribbon слева.
- Заметку можно перетащить в сайдбар; вкладки переставляются; вкладку из сайдбара можно утащить в основную область; вкладку можно закрепить (pin), чтобы её не заменяло новое содержимое.
- На мобильных и малых планшетах сайдбары свёрнуты по умолчанию.

**JetBrains** [Д]:

- 5 режимов tool window: Dock Pinned (по умолчанию, всегда виден), Dock Unpinned (виден только когда активен), Undock (перекрывает редактор), Float (плавающее окно), Window (отдельное окно приложения).
- Раскладку можно сохранить как именованный layout.

**Что взять:** числа VS Code; «unpinned» как режим для правой панели на средних экранах; pin вкладок в сайдбаре (чтобы поиск по знаниям не вытеснял список чатов).

### 2.10. Kanban: Trello, Linear, Notion

- **Trello:** колонка фиксированной ширины **272px**, зазор **8px**, контейнер — `grid-auto-flow: column` + горизонтальный скролл [3]. Ширина не ресайзится — это осознанное решение, но на 1366px влезает 4 колонки, дальше скролл.
- **Linear:** ставка на клавиатуру — `/` открывает поиск, `C` создаёт задачу, `Alt+C` — из шаблона, `Ctrl/Cmd+F` — поиск внутри текущего вида (board/list), `O` затем `I` — недавние [Д]. В командном меню префиксы `i`, `p`, `u`, `t`, `l`, `f`, `d` сужают поиск до issues/projects/users/teams/labels/favorites/documents [Д].
- **Notion:** доска группируется по **любому** свойству (status, assignee, priority, select, person, relation), поддерживает **подгруппы** (второй уровень группировки); drag&drop блоков — базовое поведение [Д].

**Что взять:** 272/8 для колонок; `C`/`/`/`Ctrl+F` как минимальный набор горячих клавиш для задач; группировку по произвольному полю (у нас — статус, роль, проект).

## 3. Выводы с числами

1. **Ширина боковой панели: 240–300px, старт 260px.** Замеренные значения: Jan 240 [К], Open WebUI 245 [К], AnythingLLM 292 [К], VS Code 300 [К]. Минимум у Open WebUI — 220 [К]. → Берём `260px`, `min 220`, `max 340` (у нас нет длинных названий моделей, 480 — избыточно).
2. **Иконочный рейл: 44px.** Open WebUI — 42px [К], VS Code — 48px, компакт 36px [К]. → `44px` с иконками 20px; подписи — только в тултипах.
3. **Правая панель: 300px.** VS Code Secondary Sidebar / Auxiliary Bar — 300px [К]. → `300px`, `min 260`, `max 420`, скрыта по умолчанию на окнах <1280.
4. **Нижняя панель: 280–300px, статус-бар 22–24px.** VS Code Panel — 300px, Status Bar — 22px [К]. → `drawer 280px` (запоминать последнюю высоту), статус-бар `24px` (крупнее ради DPI 125–150%).
5. **Мобильный брейкпоинт: 768px.** Open WebUI переключает `mobile` при `innerWidth < 768` [К]. → `<768` — оверлей-сайдбар, одна колонка, нижняя панель на всю ширину.
6. **Адаптивная ширина панели вместо фиксированной:** VS Code считает стартовую ширину как `min(300, ширина/4)` [К]. → Правило `clamp(220px, 18vw, 300px)`: на 1024px это 184→220, на 1440px — 259.
7. **Kanban-колонка 272px + 8px зазор, фиксированная, горизонтальный скролл** [3]. → На 1366px видно 4 колонки; больше — скролл, заголовки колонок sticky.
8. **Модель — в композере, а не в шапке.** Так сделали Open WebUI с v0.11 (явно обосновали) [Д], Jan (`ComposerModelPicker`) [К], Chatbox [Д]. LM Studio и GPT4All держат её в верхней панели [Д][С]. → Переносим `modelRow` внутрь композера, в шапке оставляем только индикатор загруженной модели.
9. **Три зоны одновременно — предел.** VS Code держит Activity Bar + 2 сайдбара + панель + статус-бар, но это IDE. Из LLM-приложений никто не показывает больше двух боковых зон [Д]. → У нас: рейл + один контекстный сайдбар + правая панель (скрываемая) + нижняя панель.
10. **Ширина колонки чата: 720–820px.** VS Code задаёт чату 30% ширины окна [К]; Open WebUI в v0.11 **сузил** колонку беседы [Д]. Наш текущий `max-width: 980px` для всего вида — широковато для чтения; → текст сообщений ограничить `760px`, карточки/таблицы могут быть шире.
11. **Контекст — над вводом, а не в модалке.** KoboldCpp держит блок Context (memory/world info) прямо над полем ввода [Д]; LM Studio — чипы инструментов в композере [С]. → «Знания: 3 источника · Инструменты: 5» строкой над `textarea`.
12. **Раскладка должна переживать перезапуск.** Open WebUI пишет ширину сайдбара в `localStorage` [К], VS Code — в профиль [К], JetBrains умеет сохранять layout [Д]. → У нас `data/config.json` (портативность), а не localStorage.
13. **Плотность — один глобальный множитель, а не настройка каждой панели.** Open WebUI масштабирует интерфейс одной переменной `--app-text-scale` (слайдер UI Scale) [К]; у нас уже есть `body.bigFont / body.hugeFont` [К]. → Оставить 3 ступени (Normal / Large / X-Large), ввести `--ui-scale` и считать от него отступы.
14. **Горячие клавиши — обязательны для частых действий.** Linear: `/`, `C`, `Ctrl+F` [Д]; LM Studio: `Ctrl+N`, `Ctrl+Shift+N` [Д]; VS Code: `Ctrl+B`, `Ctrl+J`, `Ctrl+Alt+B` [Д]. Open WebUI в v0.11 сделал их переназначаемыми [Д]. → Минимальный набор в §5.4.

| **Три управляющих элемента в трёх углах шапки** | GPT4All: модель — центр/верх, история — левый верх, LocalDocs — правый верх [Д] | Мышечное движение по всей ширине окна | Максимум два угла: слева — навигация, справа — контекст/инструменты |

### 5.5. Модель и загрузка (самое частое действие)

1. Пикер модели — **внутри композера**, слева от кнопки отправки (OWUI v0.11 [Д], Jan [К], Chatbox [Д]).
2. Состояние модели — в статус-баре: `Qwen2.5-7B · 4.6 ГБ · GPU 24/32 слоя` + цветная точка (как `dot` в нашей шапке [К]).
3. Если модель не загружена — вместо пикера крупная кнопка `Загрузить Qwen2.5-7B (~4.6 ГБ)`, после загрузки она превращается в чип с «Выгрузить» (паттерн LM Studio «Eject» [Д][С]).
4. Прогресс загрузки — в нижней панели, не модалкой: загрузка идёт 10–60 с, блокировать UI нельзя.
5. Оценку «поместится ли в RAM/VRAM» показывать **до** загрузки (у нас уже есть `hardware.py`), как бейдж «fits» у LM Studio [П — по описанию в COMPETITORS.md].

### 5.6. Kanban (раздел «Задачи»)

- Колонки: **272px**, зазор 8px, горизонтальный скролл контейнера; заголовок колонки sticky, с счётчиком и «+».
- Перетаскивание: карточка тащится за любую точку, у цели подсветка 2px акцентом; автоскролл у краёв; после drop — оптимистичное обновление + запись в API.
- Клавиатурный эквивалент: `C` — новая задача (Linear [Д]), `Ctrl+F` — фильтр по текущей доске [Д], в меню карточки — «Переместить в →» (иначе drag&drop недоступен с клавиатуры и на тачпаде неудобен).
- Группировка по произвольному полю: статус / роль / проект (Notion [Д]); у нас роли уже есть — это естественная вторая ось.
- Виртуализация списка карточек при >100 на доске [П — у Trello/Notion не проверял, но при ванильном JS без неё будут лаги].

### 5.7. Хранение раскладки

`data/config.json`:

```json
"ui": {
  "rail": true,
  "sidebar": {"width": 260, "collapsed": false},
  "right": {"width": 300, "open": false, "tab": "context"},
  "drawer": {"height": 280, "open": false, "tab": "tasks"},
  "scale": 1.0,
  "tabs": ["chat", "models", "team", "tasks", "kb"]
}
```

Причина: приложение портативное, `data/` едет вместе с папкой; localStorage в WebView2 привязан к профилю и может обнулиться при смене порта/переустановке [П — требует проверки на нашей сборке].

### 5.8. Что конкретно поменять в текущем UI

1. `modelRow` (index.html, строки 43–49) → перенести внутрь `.composer`; в шапке оставить только `status`/`dot`.
2. 6 верхних вкладок → рейл 44px + контекстный сайдбар; «Настройки» и «?» уходят вниз рейла (как в LM Studio и Chatbox [С][Д]).
3. `.view { max-width: 980px }` → 760px для сообщений, 1100px для карточек моделей/задач.
4. Добавить правую панель (Контекст / Инструменты / Параметры). Сейчас температура и контекст лежат в свёрнутом блоке «Настройки модели» нижнего drawer (`index.html:241`, `renderTuning()` в `app.js`) — далеко от чата [К]; перенести в правую панель, в drawer оставить задачи и логи.
5. `drawerCol { max-height: calc(52vh - 48px); overflow-y: auto }` → убрать вложенный скролл, оставить один на drawer.
6. Свести брейкпоинты 1100/1040/900 к таблице §5.3.
7. `body.bigFont/hugeFont` → `--ui-scale` (1.0 / 1.15 / 1.3), отступы считать через `calc()`.
8. Добавить `Ctrl+K`, `Ctrl+B`, `Ctrl+J`, `Ctrl+Alt+B`; подсказку — в `title` кнопок.
