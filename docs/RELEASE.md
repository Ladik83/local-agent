# Выпуск обновления LocalAgent

Порядок сборки дистрибутива, подготовки манифеста и проверки обновления.
Все команды выполняются из корня проекта (`C:\Users\volko\LocalAgent`).

## Что нужно один раз

1. Ключи подписи (Windows, ECDSA P-256 через CNG):

   ```
   python sign_update.py keygen
   ```

   Появятся `update_public.key` (публичный, его вставляют в настройки приложения)
   и `update_private.key` (приватный). Приватный ключ **не** коммитить, **не**
   класть в архив и **не** публиковать. Если он потерян — выпустить новый ключ
   и разослать новый публичный ключ пользователям.

2. Место раздачи: любой HTTPS-хостинг, куда можно положить zip и `manifest.json`.
   Для локальной проверки годится `http://127.0.0.1:8000/...` (обновление
   принимает только `https://` и локальный `http://127.*` / `http://localhost`).

## Порядок выпуска

### 1. Поднять версию

Записать новую версию в файл `VERSION` (одна строка, без `v`):

```
0.7.0
```

Версия в `VERSION` и в манифесте должна совпадать — по ней приложение решает,
что есть обновление.

### 2. Чистая сборка

```
python build_portable.py --clean
```

`--clean` не переносит `data/`, `dist/`, `.git/`, `__pycache__/`, `*.pyc`,
`*.log`, `venv/`, `.env`, `tests/` и удаляет из `dist/LocalAgent` остатки
прошлых сборок (`data/`, `models/`, `app.old/`, старый `app/`). Движки
(`--engines`) в чистой сборке намеренно не копируются.

Проверить, что пользовательских данных нет:

```
dir dist\LocalAgent
```

В списке не должно быть `data\` (с `access.token`, `settings.json`, `chats/`,
`engines/`). Файлы `start.bat`, `stop.bat`, `shortcut.bat`, `portable.txt`,
`run.py`, `VERSION`, `python\`, `app\` — на месте. Папку `data/` при первом
запуске создаст сам лаунчер.

### 3. Собрать архив

```
powershell -NoProfile -Command "New-Item -ItemType Directory -Force release | Out-Null; Compress-Archive -Path dist\LocalAgent\* -DestinationPath release\LocalAgent-0.7.0.zip -Force"
```

Внутри архива должен быть `app\main.py` (установщик ищет папку `app`).
Архив собирается **до** манифеста: любая перепаковка меняет sha256.

### 4. Сгенерировать и подписать манифест

```
python make_manifest.py --zip release\LocalAgent-0.7.0.zip --version 0.7.0 --url https://example.com/LocalAgent-0.7.0.zip --notes "Что нового в 0.7.0" --out release\manifest.json --sign
```

- `--zip` — путь к готовому архиву, `--version` — версия из `VERSION`,
  `--url` — публичная ссылка на этот же архив, `--notes` — текст «что нового».
- `--sign` берёт `update_private.key` из корня проекта (или путь из `--key`)
  и добавляет поле `signature`.
- Код возврата `0` — успех, `2` — ошибка (нет архива, кривая версия, нет
  ключа, CNG недоступна); текст ошибки печатается в stderr.

Результат — JSON в UTF-8:

```json
{
  "version": "0.7.0",
  "url": "https://example.com/LocalAgent-0.7.0.zip",
  "sha256": "…64 hex…",
  "notes": "Что нового в 0.7.0",
  "signature": "…base64…"
}
```

### 5. Выложить файлы

Загрузить на хостинг **оба** файла: `LocalAgent-0.7.0.zip` и `manifest.json`.
Ссылка в манифесте (`url`) должна указывать на этот же загруженный zip.
Если zip перезалит заново — пересобрать манифест (sha256 изменится).

### 6. Настроить приложение у пользователя

«Настройки» → «Адрес манифеста обновлений» — ссылка на `manifest.json`
(например `https://example.com/manifest.json`);
«Настройки» → «Открытый ключ обновлений» — содержимое `update_public.key`
(одна строка base64), либо строка, которую напечатал `python sign_update.py keygen`.

Если ключ задан, приложение принимает только подписанные манифесты; если
поле пустое — проверка подписи не выполняется (менее безопасно).

### 7. Проверить обновление

«Настройки» → «Проверить обновления»: приложение скачает манифест, сверит
подпись, сравнит версии, затем скачает архив, сверит sha256, сделает бэкап
`data/backup/app-<версия>.zip` и подменит папку `app`. Если файлы заняты —
обновление применится после перезапуска (`data/pending_update.json`).

## Чек-лист выпуска

- [ ] Версия в `VERSION` поднята и совпадает с `--version` в манифесте.
- [ ] Сборка сделана с `--clean`; в `dist/LocalAgent` **нет** `data\`,
      `access.token`, `settings.json`, `chats\`, `engines\`, `.git`, `__pycache__`,
      `*.pyc`, `*.log`.
- [ ] `portable.txt`, `start.bat`, `run.py`, `app\`, `python\` в сборке есть.
- [ ] Архив собран **после** сборки и **до** манифеста; sha256 в манифесте
      совпадает с `certutil -hashfile release\LocalAgent-0.7.0.zip SHA256`.
- [ ] Манифест подписан (`signature` не пустая), `python make_manifest.py … --sign`
      вернул 0.
- [ ] `update_private.key` не попал в архив, в `release\` и в репозиторий.
- [ ] Приложение с вставленным публичным ключом принимает манифест
      (проверка подписи проходит), а манифест с изменённым `url` — отклоняет.
- [ ] Обновление ставится на чистой машине: распаковать архив в новую папку,
      запустить `start.bat`, задать адрес манифеста и ключ, проверить обновление.
- [ ] После установки `VERSION` в папке обновлён, приложение запускается,
      данные пользователя (`data/`) не тронуты.
- [ ] Запуск `python tests/check_release.py` завершается кодом 0.

## Частые ошибки

| Сообщение | Причина и что делать |
| --- | --- |
| «Подпись манифеста не совпала» | Ключ в настройках не от той пары; манифест правили после подписи; версия/url/sha256 в файле изменены. Пересобрать манифест с `--sign`. |
| «Хэш архива не совпал с манифестом» | Zip перепаковали после генерации манифеста. Пересобрать манифест. |
| «В манифесте нет поля version» | Битой JSON или чужой файл по ссылке. |
| «Разрешены https и локальный http» | Указан `http://` на внешний хост — нужен HTTPS. |
| `make_manifest` вернул 2 | Смотрите текст в stderr: нет архива, версия не вида `0.7.0`, пустой `--url`, нет `update_private.key`, нет CNG. |
