# Рабочее пространство «Локального агента»: три компоновки и Kanban-блоки

Документ описывает дизайн-проект главного экрана: варианты A / B / C, состав блоков,
правила плотности и размеров, поведение на узких экранах и перенос в текущее приложение.
Рабочий макет: [`docs/mockups/layout_v1.html`](mockups/layout_v1.html) — один файл,
открывается двойным кликом, работает без сети.

---

## 1. Задача и принципы

Пользователь — не программист. Ему нужно «разобраться с первого взгляда»: крупные подписи,
понятные иконки, «?» у каждой настройки и ничего лишнего. При этом интерфейс должен оставаться
частью приложения, а не выглядеть чужим сайтом.

Отсюда пять правил, на которых держится макет:

1. **Один экран вместо десяти.** Всё, что нужно в работе, — модель, знания, задачи, чаты,
   проекты, роли, голос, инструменты — лежит блоками на одном рабочем пространстве.
2. **Kanban-логика.** Блок — это карточка с заголовком. Её можно перетащить в левую панель,
   правую панель или нижнюю шторку. Порядок внутри панели тоже меняется. Раскладка
   запоминается.
3. **Ничего не прыгает.** Панели и шторка имеют ручные разделители; при перетаскивании
   остаётся пунктирный «слот», поэтому видно, куда встанет карточка.
4. **Новичку — подсказка в один клик.** У каждого блока и у ключевых элементов есть «?»
   с коротким объяснением простым языком.
5. **Офлайн и без зависимостей.** Только HTML/CSS/JS, системный шрифт Segoe UI,
   юникод-символы вместо иконочных шрифтов. Палитра — ровно та же, что в `app/ui/style.css`.

## 2. Что переносим из текущего интерфейса

Макет не придумывает новый язык — он перекладывает существующие элементы в блочную сетку.

| Сейчас (`app/ui/`) | В макете | Что меняется |
|---|---|---|
| Палитра `:root` (`--bg #0f1115`, `--panel #171a21`, `--panel2 #1e222b`, `--text #e8ecf3`, `--muted #98a2b3`, `--accent #5b8cff`, `--ok #3ecf8e`, `--warn #ffb454`, `--err #ff6b6b`, `--line #262b36`) | те же переменные, без новых базовых цветов | добавлены только полупрозрачные оттенки `rgba(91,140,255,…)`, `rgba(255,180,84,…)`, `rgba(62,207,142,…)` |
| Шрифт `15px/1.55 "Segoe UI", system-ui` | тот же, размер задаётся переменной `--fs` | плотность меняет `--fs`, а не семейство шрифта |
| Вкладки «Чат, Модели, Знания, Задачи, Команда, Настройки» | в C — полноэкранные вкладки; в A/B разделы заменены блоками (Модель, Знания, Задачи, Роли), настройки — шестерёнка в шапке чата | названия сохранены; в A/B навигация уходит в блоки |
| Панель режимов «Один помощник / Команда специалистов» | блок в композере, с «?» | без изменений по смыслу |
| Шаблоны запросов (чипы) | строка чипов над моделью | на средней ширине скрывается, чтобы не отнимать высоту у чата |
| Строка модели (select + «Загрузить/Выгрузить») | остаётся над полем ввода | в макете подпись «Модель» и кнопка «Выгрузить» |
| Композер `+ 📎 🎤 Отправить` | тот же набор | кнопки получили подсказки |
| Нижняя шторка из трёх колонок с разделителями | блоки `now`, `tools`, `voice` в нижней панели; разделители — между панелями | колонки заменены карточками, которые можно менять местами |
| Статусная строка (модель, ЦП, ОЗУ, токены, скорость, порт) | та же строка внизу | остаётся всегда на месте |
| `.help` с `data-tip` | тот же принцип, но подсказка одна на страницу и не обрезается у края | позиция пересчитывается и переворачивается вниз у верхней кромки |
| `.light`, `.bigFont` | `.light` сохраняется; `bigFont` заменяется плотностью «Просторно» | одна система вместо двух |

Новые цвета не вводились. Тёмно-синий пузырь пользователя (`#23304a` / `#2c3c5c`) взят
из текущего `style.css`.

## 3. Блоки рабочего пространства

Десять блоков закрывают ежедневные сценарии. Каждый — самостоятельная карточка с иконкой,
названием, «?» и сворачиванием.

| id | Название | Содержимое | Зачем новичку |
|---|---|---|---|
| `model` | Модель | имя модели, статус «загружена», память, «Сменить / Выгрузить» | понять, работает ли «мозг» агента |
| `resources` | Ресурсы | ЦП, ОЗУ, видеокарта, полосы загрузки | увидеть, не перегружен ли компьютер |
| `knowledge` | Знания | число папок и файлов, поиск, «Открыть базу» | найти документы, которые агент уже прочитал |
| `tasks` | Задачи | три задачи по расписанию с переключателями | включить автоматические сводки |
| `chats` | Чаты | история чатов, активный чат, «Новый чат» | вернуться к прошлому разговору |
| `projects` | Проекты | рабочие папки и пути | дать агенту доступ к нужной папке |
| `roles` | Роли команды | чипы ролей (аналитик, разработчик, ревьюер) | понять, кто будет решать сложную задачу |
| `voice` | Голос | кнопка «Сказать», горячие клавиши, озвучка | говорить вместо печати |
| `tools` | Инструменты | файлы, командная строка, интернет, MCP | разрешить только нужное |
| `now` | Сейчас | статус, мини-график скорости, токены, последнее действие | понять, что происходит прямо сейчас |

Порядок по умолчанию — по частоте использования: модель и чаты выше, ресурсы и знания рядом,
инструменты и голос — внизу. Пользователь может переставить всё под себя.

### Подтверждение действия

Запрос разрешения («Записать `сводка.md`?») вынесен **из прокрутки чата** в отдельную
полосу над полем ввода. Причина: подтверждение не должно уезжать вверх при прокрутке
длинного ответа. Это единственное заметное изменение по сравнению с текущим чатом.

## 4. Три варианта компоновки

Переключатель A / B / C — в шапке. У каждого варианта **своя** сохранённая раскладка:
переключение не ломает то, что уже настроено.

### Вариант A — две боковые панели + центр

```
┌──────────────────────────────────────────────────────────────────┐
│ шапка: A · Две панели   плотность   модель   ?   сброс           │
├───────────┬──────────────────────────────────┬───────────────────┤
│ Левая     │            Чат                   │ Правая            │
│ 280 px    │            центр                 │ 300 px            │
│           │                                  │                   │
│ Модель    │  сообщения                       │ Ресурсы           │
│ Чаты      │                                  │ Знания            │
│ Проекты   │  режимы / шаблоны                │ Задачи            │
│ Роли      │  модель + композер               │                   │
├───────────┴──────────────────────────────────┴───────────────────┤
│ Нижняя шторка 236 px: Инструменты · Голос · Сейчас               │
├──────────────────────────────────────────────────────────────────┤
│ статусная строка                                                 │
└──────────────────────────────────────────────────────────────────┘
```

**Размеры:** левая 280 px (200–440), правая 300 px (220–480), шторка 236 px (120–55 vh),
разделители 5 px.

**Плюсы:** всё видно сразу; классическая «рабочая станция»; хорошо для 1440 px и шире.
**Минусы:** три зоны отнимают ширину у чата; на 1000 px правая панель уже мешает.
**Когда:** основной вариант для настольного ПК, если модель и ресурсы нужны постоянно.

### Вариант B — одна левая панель + нижняя шторка

```
┌──────────────────────────────────────────────────────────────────┐
│ шапка: B · Шторка                                                │
├───────────┬──────────────────────────────────────────────────────┤
│ Левая     │                     Чат                              │
│ 300 px    │              максимально широкий                     │
│           │                                                      │
│ Модель    │  сообщения                                           │
│ Чаты      │                                                      │
│ Проекты   │  режимы / шаблоны / модель / композер                │
│ Роли      │                                                      │
├───────────┴──────────────────────────────────────────────────────┤
│ Нижняя шторка 260 px: Ресурсы · Знания · Задачи · Инструменты ·  │
│                       Голос · Сейчас                              │
├──────────────────────────────────────────────────────────────────┤
│ статусная строка                                                 │
└──────────────────────────────────────────────────────────────────┘
```

**Размеры:** левая 300 px, шторка 260 px, правая панель отсутствует.

**Плюсы:** самый широкий чат; меньше всего «рамок»; нижняя полоса хорошо работает как
горизонтальная лента карточек (шесть блоков в ряд на 1440 px).
**Минусы:** нижняя шторка перегружена; часть блоков видна только после прокрутки; на
низком экране (768 px) чат сжимается.
**Когда:** если чат — главное, а панели нужны «под рукой», но не постоянно.

### Вариант C — полноэкранные вкладки + плавающие блоки

```
┌──────────────────────────────────────────────────────────────────┐
│ шапка: C · Плавающие                                             │
├──────────────────────────────────────────────────────────────────┤
│ Чат   Модели   Знания   Задачи   Команда   Настройки              │
├──────────────────────────────────────────────────────────────────┤
│ [Модель]   ┌──────────────────────────────┐   [Ресурсы]          │
│ [Чаты]     │      Чат 840 px, по центру   │   [Знания]           │
│ [Проекты]  │                              │   [Задачи]           │
│ [Роли]     │  сообщения / композер        │   [Инструменты]      │
│            └──────────────────────────────┘                      │
│        [Голос]              [Сейчас]                             │
├──────────────────────────────────────────────────────────────────┤
│ статусная строка                                                 │
└──────────────────────────────────────────────────────────────────┘
```

**Размеры:** карточка 270 px (246 / 292 px в компактной / просторной плотности),
чат — до 840 px, отступ от края 14 px. Блоки двигаются свободно; позиция хранится в px
относительно рабочей области.

**Плюсы:** самый «воздушный» и наглядный вариант; хорошо показывает, что блоки — это
отдельные карточки; подходит для больших мониторов и презентаций.
**Минусы:** карточки могут перекрывать чат; нужно много места; при нехватке места
вариант сам переходит в список.
**Когда:** большой экран (≥1200×860), демонстрация возможностей, «режим обзора».

Правило перехода C в список: ширина ≤ 1040 px, **или** высота ≤ 860 px, **или**
плотность «Просторно» (крупные карточки не помещаются в колонки). В списке чат идёт первым,
ниже — блоки левой, правой и нижней зон с заголовками. Остальные вкладки C («Модели»,
«Знания», «Задачи», «Команда», «Настройки») открывают полноэкранную заглушку раздела:
в макете показан сам принцип, содержимое разделов остаётся прежним.

### Сравнение

| | A. Две панели | B. Шторка | C. Плавающие |
|---|---|---|---|
| Ширина чата на 1440 px | 830 px | 1115 px | 840 px |
| Видно блоков без прокрутки | 8–9 | 8–9 | 10 |
| Порог «ломается» | 1100 px | 820 px | 1040 px / 860 px по высоте |
| Свободное перетаскивание | нет, только зоны | нет | да |
| Сложность для новичка | средняя | низкая | выше средней |
| Лучше всего для | ежедневной работы | чата | обзора и больших экранов |

## 5. Плотность

Плотность — это набор CSS-переменных на `body[data-density]`. Палитра, шрифт и логика
не меняются; меняются только размеры и отступы.

| Переменная | Компактно | Обычно | Просторно | Что задаёт |
|---|---:|---:|---:|---|
| `--fs` | 13 px | 14.5 px | 16 px | заголовки блоков, текст чата |
| `--fs2` | 12 px | 13 px | 14 px | строки, списки, подписи полей |
| `--fs3` | 10.5 px | 11.5 px | 12.5 px | сноски, чипы, статусы |
| `--gap` | 6 px | 10 px | 14 px | зазор между блоками и вокруг панелей |
| `--pad` | 8 px | 12 px | 16 px | внутренние отступы карточки |
| `--pad2` | 10 px | 14 px | 18 px | отступы чата и композера |
| `--r` | 8 px | 10 px | 12 px | радиус карточки |
| `--r2` | 10 px | 12 px | 14 px | радиус панели |
| `--headH` | 28 px | 36 px | 42 px | высота заголовка карточки |
| `--icon` | 18 px | 22 px | 24 px | плитка иконки |
| `--floatW` | 246 px | 270 px | 292 px | ширина плавающей карточки в C |

Правила:

- Плотность не меняет ширину панелей, заданную пользователем, и не сбрасывает раскладку.
- В варианте C смена плотности пересобирает свободные позиции по колонкам, иначе крупные
  карточки наезжают друг на друга.
- «Просторно» в C включает список: четыре карточки в колонке при 16 px не помещаются
  в 900 px по высоте.
- Старая настройка «крупный шрифт» (`body.bigFont`) заменяется плотностью «Просторно»;
  отдельный класс больше не нужен.

## 6. Типографика

- Семейство: `"Segoe UI", system-ui, sans-serif`. Без веб-шрифтов.
- Базовая строка `body`: `15px / 1.55` (как в приложении). Текст карточек и чата —
  `var(--fs)`: 13 / 14.5 / 16 px по плотности.
- Заголовок блока: `var(--fs)`, вес 600.
- Заголовок панели: 10.5 px, uppercase, `letter-spacing: .7px`, цвет `--muted`.
- Вторичный текст: `var(--fs2)`, цвет `--muted`.
- Сноски и чипы: `var(--fs3)`.
- Статусная строка: 11.5 px.
- Сегменты шапки: 12.5 px.
- Сообщение чата: `var(--fs)`, `line-height: 1.55`, максимум 90 % ширины.
- Заголовки разделов в справке: 17 px; текст — 13 px / 1.55.

Правило для новичка: **не мельче 11.5 px** для всего, что несёт смысл. 10–10.5 px
допустимы только для сносок и счётчиков.

## 7. Отступы, радиусы, границы

Шкала отступов: **4 / 6 / 8 / 10 / 12 / 14 / 16 / 18 / 22 px**. Значения вне шкалы
не использовать.

| Элемент | Значение |
|---|---|
| Внешний отступ рабочей области | `var(--gap)` (6/10/14) |
| Зазор между карточками | `var(--gap)` |
| Внутренний отступ карточки | `var(--pad)` по горизонтали, `var(--pad)` снизу |
| Радиус панели | 14 px (`--r2` на узких) |
| Радиус карточки | `var(--r)` (8/10/12) |
| Радиус кнопки | 8–11 px |
| Толщина границы | 1 px `--line` |
| Тень | только у плавающих карточек C и модальных окон |
| Разделитель панелей | 5 px зона захвата, 2 px видимая линия |

Цвета состояний: активный элемент — `--accent`; успех — `--ok`; предупреждение — `--warn`;
ошибка — `--err`. Фон карточек — `--panel2`, фон панелей — `--panel`, фон приложения — `--bg`.

## 9. Поведение на разных экранах

| Ширина / высота | Что происходит |
|---|---|
| ≥1280 px | полные подписи A/B/C и плотности; все три зоны A; C плавает |
| 1101–1279 px | подписи вариантов и плотности скрываются, остаются буквы и кнопки; раскладка не меняется |
| 821–1100 px, A | правая панель уходит **вниз** горизонтальной полосой 236 px; нижняя шторка сворачивается в полосу 40 px и открывается **поверх** чата (270 px); шаблоны и подсказка композера скрываются |
| 821–1100 px, B | без изменений: левая панель + шторка 260 px |
| 1041–1100 px, C | плавает, если хватает высоты; иначе список |
| ≤1040 px, C | список: чат 78 vh, ниже блоки левой, правой и нижней зон |
| ≤860 px по высоте, C | список независимо от ширины |
| ≤820 px, A/B | панели становятся вкладками: «Левая · Чат · Правая · Шторка» (в B без «Правой»). Активная вкладка занимает весь экран; разделители скрыты |
| ≤820 px, C | список (чат + блоки), вкладки C остаются сверху |
| ≤560 px | компактная шапка, скрываются текст «Сбросить раскладку» и часть статусов |

Ключевое правило: **чат не должен стать ниже ~400 px**. Поэтому на средней ширине
в A сворачивается шторка, а второстепенные строки композера прячутся. Если высоты всё равно
не хватает, приоритет у чата, а панели уходят в прокрутку.

На 780 px вкладки показывают панель целиком, с вертикальной прокруткой; перетаскивание
между вкладками в этом режиме недоступно — это осознанное ограничение мобильной раскладки.
Вернувшись на широкий экран, пользователь увидит прежнюю раскладку.

## 10. Перетаскивание блоков

Реализация — Pointer Events, без библиотек.

1. **Захват.** `pointerdown` на заголовке карточки (`.blockHead`). Кнопки «?» и «свернуть»
   игнорируются. Порог начала — 5 px, чтобы случайный клик не двигал блок.
2. **Подъём.** Карточка получает `position: fixed`, следует за курсором, становится
   полупрозрачной; на её месте остаётся пунктирный слот высотой карточки.
3. **Цель.** На каждом движении `document.elementFromPoint` ищет ближайший
   `[data-drop]` — тело левой, правой или нижней зоны. Зона подсвечивается рамкой
   `--accent`; слот переезжает в неё.
4. **Порядок.** Слот вставляется перед ближайшей карточкой. Ось выбирается по большему
   смещению: для вертикального списка — по Y, для горизонтальной ленты — по X.
   Поэтому перетаскивание работает и в колонке, и в нижней ленте, и в сетке.
5. **Отпускание.** Карточка встаёт на место слота; порядок зон сохраняется в localStorage.
   Если отпустить вне зон, карточка возвращается на прежнее место.
6. **Вариант C.** Слот не создаётся: карточка свободно летит за курсором, а после отпускания
   её координаты (x, y в px относительно рабочей области) сохраняются. Карточка возвращается
   в свой DOM-контейнер, чтобы не потерять стили.
7. **Отмена.** `Escape` во время перетаскивания возвращает карточку на исходное место.
8. **Подсказка.** После переноса показывается короткий тост «Блок «…» перенесён».

Ограничения макета: нет клавиатурного перемещения (стрелками) и нет длинного нажатия
для мобильного перетаскивания. Для production это следующие шаги, не влияющие на визуал.

### Хранение

Ключ: `localagent.mockup.layout.v1`. Одна запись JSON:

```json
{
  "variant": "A",
  "density": "normal",
  "mtab": "stage",
  "ctab": "chat",
  "dockCollapsed": false,
  "dockOpen": false,
  "collapsed": { "chats": true },
  "layouts": {
    "A": {
      "left": ["model", "chats", "projects", "roles"],
      "right": ["resources", "knowledge", "tasks"],
      "bottom": ["tools", "voice", "now"],
      "leftW": 280, "rightW": 300, "dockH": 236
    },
    "B": { "left": ["..."], "bottom": ["..."], "leftW": 300, "dockH": 260 },
    "C": {
      "left": ["..."], "right": ["..."], "bottom": ["..."],
      "free": { "model": { "x": 14, "y": 14 } }
    }
  }
}
```

Каждый вариант хранит свою раскладку. При добавлении нового блока он автоматически
попадает в зону по умолчанию, поэтому старые сохранения не ломаются.

Кнопка **«↺ Сбросить раскладку»** возвращает блоки, ширины, высоту шторки и плотность
«Обычно». Подтверждение не запрашивается — действие обратимо только вручную, но в макете
это допустимо; в приложении стоит добавить мягкий тост с отменой.

## 11. Разделители панелей

- Зона захвата — 5 px; видимая линия — 2 px `--line`, при наведении и перетаскивании —
  `--accent`.
- Левая панель: 200–440 px. Правая: 220–480 px. Шторка: 120 px – 55 vh.
- Двойной клик по разделителю возвращает размер по умолчанию.
- В варианте C разделителей нет: там свободные карточки.
- На ≤820 px разделители скрыты — панели занимают весь экран.

## 12. Подсказки и доступность

- Подсказка — один элемент `#tip` на всю страницу. Показывается по `pointerover` и `focusin`
  у любого `[data-tip]`.
- Позиция пересчитывается: над элементом; если до верхней кромки меньше 60 px —
  под элементом; по горизонтали прижимается к окну с отступом 8 px.
- Подсказка не перехватывает мышь (`pointer-events: none`) и скрывается при прокрутке,
  изменении размера и нажатии.
- У каждой карточки есть «?»; у режимов, шаблонов, кнопок композера, разделителей и
  переключателя вариантов — тоже.
- Кнопка «?» в шапке открывает короткую инструкцию: перенос блоков, размеры, A/B/C,
  плотность, сброс, адаптив.
- Все интерактивные элементы — настоящие `button`/`input`; у иконочных кнопок есть
  `aria-label`. Карточки сворачиваются кнопкой, а не кликом по заголовку, чтобы
  перетаскивание не сворачивало блок случайно.
- Контраст текста: `--text` на `--panel2` — около 12:1; `--muted` на `--panel` — около
  5.4:1, достаточно для вторичного текста. Мелкие подписи не опускаются ниже 10.5 px.

## 13. Что и как переносить в приложение

Макет — один файл, но структура уже разложена так, чтобы перенос был механическим.

1. **CSS-переменные.** Перенести блок `:root` и `body[data-density]` в `app/ui/style.css`.
   Существующие классы (`.panel`, `.row`, `.help`, `.statusbar`) не удалять: они используются
   на внутренних экранах. Новые классы — только для рабочего пространства
   (`.work`, `.zone`, `.block`, `.res`).
2. **Реестр блоков.** В `panels.js` завести объект `BLOCKS` (id, заголовок, иконка, подсказка,
   HTML содержимого) и `DEFAULTS` — раскладки A/B/C. Рендер зон делать из этих данных,
   как в макете. Сейчас `panels.js` уже собирает шторку из трёх колонок — логика похожая.
3. **Состояние.** Хранить `variant`, `density`, `layouts` в localStorage под отдельным ключом
   (`localagent.layout.v1`). При первом запуске — раскладка A. При добавлении блока —
   добивать в зону по умолчанию.
4. **Перетаскивание.** Перенести функции `onPointerDown` / `onPointerMove` / `onPointerUp`
   без изменений; они не зависят от содержимого карточек. Единственное требование —
   заголовок карточки должен быть `.blockHead`, а зоны — `[data-drop]`.
5. **Адаптив.** Сохранить пороги 1100 / 1040 / 860 (высота) / 820 px. Проверить,
   что чат не становится ниже 400 px: в A на средней ширине шторка сворачивается,
   в C включается список.
6. **Чат.** В макете сообщения статичны. В приложении на это место встаёт текущий
   `#messages`; композер и строку модели можно оставить как есть, добавив полосу
   подтверждения над `modeRow`.
7. **Темы.** `.light` продолжает работать: все новые цвета — переменные. Проверить
   контраст `--warn` на светлом фоне; при необходимости затемнить до `#b26a00` только
   в `.light`.
8. **Плотность вместо `bigFont`.** Настройку «Размер текста» заменить на три кнопки
   плотности. «Просторно» (16 px) соответствует прежнему крупному шрифту; 17/19 px
   можно сохранить как отдельную настройку доступности поверх плотности.

Порядок безопасного внедрения: сначала CSS-переменные и плотность (без изменения логики),
затем блоки в левой панели, затем перетаскивание, затем адаптив. Каждый шаг можно
проверить в браузере без бэкенда.

## 14. Что не вошло в макет

- Реальные данные модели, ресурсов и базы знаний — числа демонстрационные.
- Сохранение на сервере: раскладка живёт в localStorage браузера.
- Клавиатурное перемещение блоков и мобильное длинное нажатие.
- Светлая тема в макете не переключается, но все цвета — переменные, поэтому `.light`
  подхватится без правок.
- Анимации ограничены 120–200 мс; при `prefers-reduced-motion` отключаются.
