## Найденные дефекты

### P1 — мешает работе, функция не работает

#### P1-1. Сохранённая тема, скин и размер шрифта не применяются при запуске
- **Где:** `app/ui/app.js`, `wireGear()` (строка ~1402) и `applyLook()` (~1350).
- **Причина:** `wireGear()` в конце вызывает `applyLook()`, но падает раньше на строке `trayBox.checked = !!(STATE.settings && STATE.settings.tray);` — `STATE` на момент boot ещё `null` (`let STATE = null`, заполняется позже в `loadState()`). `bootStep()` глушит исключение в `console.error`, поэтому `applyLook()` не выполняется никогда, а `#gearTray` не синхронизируется с настройкой.
- **Симптом:** пользователь выбрал светлую тему / «Океан» / крупный шрифт — после перезапуска всё снова тёмное и мелкое; в списке «Тема» стоит «как в системе» вместо сохранённого значения.
- **Доказательство:** `boot:gear TypeError: Cannot read properties of null (reading 'settings')`; после перезагрузки с `agentTheme=light` — `body: ""`, `bg: rgb(15, 17, 21)`, `#gearTheme.value: "auto"`. Ручной вызов `applyLook()` сразу даёт `skin-sand light hugeFont`.
- **Что проверить после исправления:** перезагрузка с сохранёнными `agentTheme/agentSkin/agentFont` → в `body.className` есть `light`, `skin-ocean`, `hugeFont`; `#gearTheme` показывает сохранённое значение; в консоли нет ни одного `boot:*`; галочка «Иконка в трее» отражает `settings.tray`.

#### P1-2. Переключатель модели распознавания речи падает с `ReferenceError`
- **Где:** `app/ui/app.js:1026` — `picker.addEventListener('change', saveVoiceModel);`, функция `saveVoiceModel` нигде не определена (есть только `saveVoiceTts`).
- **Симптом:** при каждой отрисовке панели «Голос» (вкладка «Настройки», `loadVoice().then(renderVoice)`) в консоль летит `ReferenceError: saveVoiceModel is not defined`; смена «точности распознавания» ничего не делает.
- **Доказательство:** статический прогон обработчиков — «не определены: `['saveVoiceModel']`»; в браузере — `ReferenceError: saveVoiceModel is not defined`.
- **Что проверить:** смена значения в `#voiceModel` → `POST /api/settings {voice_model: …}` и тост; консоль чистая; после перезагрузки выбранная модель отмечена `selected`.

#### P1-3. Кнопки «Сохранить задачу» и «Сохранить и проверить» не нажимаются (нет обработчиков)
- **Где:** `app/ui/index.html:123` (`#taskSave`), `app/ui/index.html:179` (`#tgSave`); функции `saveTask()` и `saveTelegram()` в `app.js` определены, но **ни разу не используются** (нет `addEventListener`/`onclick`).
- **Симптом:** заполнил задачу по расписанию, нажал «Сохранить задачу» — ничего не происходит, задача не появляется; то же с Telegram-токеном.
- **Доказательство:** клик по обеим кнопкам → массив вызовов `postJson` пуст (`{"taskCalls": [], "allCalls": []}`); `grep` подтверждает, что имена встречаются только в определении функций.
- **Что проверить:** клик по `#taskSave` → `POST /api/schedule/save`, тост «Задача сохранена», запись появляется в `#taskList`; клик по `#tgSave` → `POST /api/telegram`, тост и обновление `#tgState`.

#### P1-4. «Доступ с телефона по локальной сети» не работает, но ссылки выдаются
- **Где:** `app/main.py:39` — `HOST = "127.0.0.1"` (константа), `run()` всегда делает `Server((HOST, port), Handler)`; `settings.lan_access` учитывается только в `/api/lan` (`main.py:342`), который формирует URL с IP и токеном.
- **Симптом:** включённый тумблер «Доступ с телефона» обещает ссылку, но телефон не подключится: процесс слушает только loopback. При этом в интерфейсе показывается ссылка с токеном вида `http://192.168.3.206:7888/?token=…` — пользователь считает, что дело в телефоне.
- **Доказательство:** `netstat -ano | grep :7888` → `TCP 127.0.0.1:7888 … LISTENING`; `curl http://192.168.3.206:7888/` → `000`; `/api/lan` → `{"enabled": true, "urls": ["http://192.168.3.206:7888/?token=8c2d…", …]}`.
- **Что проверить:** при `lan_access=true` сервер слушает `0.0.0.0` (проверить `netstat`), телефон открывает ссылку и получает UI; при `lan_access=false` порт снаружи закрыт; защита от чужого `Host` (403) и требование токена (401) продолжают работать; ссылки в `/api/lan` не отдаются, когда доступ выключен.

## Замечания по поведению (не дефекты)

- **Отключённый диск моделей обработан корректно:** `dir_ok=false`, `mode=off`, понятная подсказка в UI, поиск остаётся на BM25 — приложение не падает и не зависает. Если диск `F:` отключён, это не баг приложения.
- **`/api/job` и `/api/jobs` — разные контракты** (`{engine, download, discover}` против `{jobs: {...}}`), но оба используются по назначению: `poll()`/`discoverPoll()` читают первый, `waitJob()` — второй. Не путаница, а два разных механизма.
- **Токен в разметке:** `index.html` отдаётся с `<meta name="agent-token">`; для loopback это нормально, для LAN-режима (после исправления P1-4) стоит перепроверить, что мета не отдаётся без авторизации.
- **`/api/attach` читает только разрешённые пути** (`tools._resolve`), произвольного чтения файлов нет — проверено на `C:\Windows\win.ini`.
- **Эмбеддинги в двух экземплярах разные:** мой экземпляр (порт 7888) взял `embeddinggemma-2-BF16.gguf`, работающий экземпляр пользователя (порт 7867) — `nomic-embed-text-v2-moe.Q8_0.gguf`, при одинаковом `dim=768`. Это не ошибка теста, а следствие P2-15: `embed.find_model()` берёт первый подходящий `.gguf` в порядке обхода папки.
